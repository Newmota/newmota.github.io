    Roadmap and Release Stages¶

    Draft

    This page is a draft. The stage boundaries are set; the conditions for moving from one stage to the next are proposals.

    Newmota's version number tells you how far you can trust a build. The version is shown in the boot log, in Status 2 ("Version") and in the web interface.

    No stage makes over-the-air updates safe

    Newmota does not promise that an over-the-air update succeeds, in any stage, stable included; no firmware project can. A power cut, a weak Wi-Fi link, a flash fault or a bug can leave a device that only a wired flash brings back. Before you install Newmota on a device, know how you would flash it over a wire, and keep a backup of the original firmware and your settings.

    Stages¶

    Version Stage Use it on
    0.0.x Pre-alpha Development boards only
    0.1 – 0.7.x Alpha Devices you can easily flash over a wire again
    0.8 – 0.9.x Beta Everyday devices, but expect frequent problems
    1.0 and later Stable Normal use

    Pre-alpha (0.0.x)¶

    There is no real release yet. Every build is 0.0.1, so two builds with the same number can differ completely. Commands, settings and file formats can change at any time, and an update can lose the device's settings. Use a development board with a USB serial port.

    Alpha (0.1 – 0.7.x)¶

    Releases have their own version numbers. Features still change, and settings and file formats can still change from one release to the next. An over-the-air update or the recovery path can fail and leave the device needing a wired flash, so only use devices whose serial pins you can reach easily.

    Beta (0.8 – 0.9.x)¶

    Features are mostly complete, and over-the-air updates and Safeboot recovery have been tested on every supported family. Bugs are still frequent, so keep a backup of the original firmware and your settings.

    Stable (1.0 and later)¶

    Updates within a major version keep your settings and commands working. An over-the-air update can still fail; see the warning at the top of this page.

    Rough timeline¶

    A target, not a promise; dates move when the conditions below are not met.

    Stage Target
    Alpha (0.1) January 2027
    Beta (0.8) March 2027
    Stable (1.0) January 2028

    Moving to the next stage¶

    Pre-alpha to alpha (0.1)¶

    • A release is built from a tagged commit, and its packages carry that version.
    • On at least one board for each platform family (ESP32, Beken, Bouffalo, Raspberry Pi Pico, AmebaD), the core passes a hardware test: boot and restart, Wi-Fi, web interface, console, MQTT, the file system, and a wired factory flash.

    Alpha to beta (0.8)¶

    • Over-the-air update and Safeboot recovery pass hardware tests on every supported family, including power loss during an update.
    • The open hardware checks for the features in the default builds are done.

    Beta to stable (1.0)¶

    • The settings and file formats are fixed, and commands keep their meaning within the major version.
    • No known problem leaves a device unrecoverable without a wire.
