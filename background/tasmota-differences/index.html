    Coming from Tasmota¶

    Newmota treats Tasmota as its behavioral reference: every feature starts from Tasmota's documentation and current source, and deviations are deliberate and recorded. If you arrive from Tasmota, most of your muscle memory transfers — this page lists what doesn't. To move a device, see Switching From Tasmota.

    Newmota is an independent project. It is not part of, affiliated with or endorsed by Tasmota or OpenBeken, so please report problems with Newmota to the Newmota project and not to them. Newmota owes a lot to both: Tasmota for the commands, templates and Berry integration it follows, and OpenBeken for its work on Beken and other Tuya-module chips.

    Building your own image

    Tasmota offers ready-made binaries for most devices and tailored builds through user_config_override.h. Newmota has no downloads yet, so you build your own image, and make config makes that easy: pick your chip and features from a menu, and Newmota checks the combination before it compiles. See Build Your Firmware.

    What carries over unchanged¶

    • Console habits: case-insensitive commands, JSON replies, the _ quiet prefix, ? queries.
    • Status 1/2/3/4/5/7/8/10/11 telemetry sections and their JSON shapes.
    • SetOption0…177 numbering and boolean/parameter semantics.
    • Wi-Fi slots (SSId1/Password1, SSId2/Password2), Timezone/TimeStd/TimeDst/NtpServer, SerialLog/WebLog numbering.
    • Module / Template / GPIO workflow, template JSON shape, and the frozen 16-bit GPIO function IDs. Per-pin GPIO overrides still apply only to User slots.
    • Power stack: Power, PowerOnState 0…5, PulseTime, BlinkTime/BlinkCount, Interlock.
    • Light stack: Dimmer, Channel, Color, CT, White, HsbColor, Fade, Speed, LedTable, Scheme 0..14, Wakeup.
    • Sensors: StatusSNS, MQTT tele/<topic>/SENSOR, SetOption8 (°C/°F), SetOption24/SetOption139 (pressure units), TempRes/HumRes/PressRes, TempOffset/HumOffset.
    • MQTT topic convention: cmnd/<topic>/#, stat/<topic>/RESULT, stat/<topic>/POWER, tele/<topic>/STATE, tele/<topic>/SENSOR.
    • Reset 1…6 meanings (including keep-Wi-Fi variants 4–6) and Restart 1 / Restart 99.
    • Berry: the Br command, /autoexec.be startup script, and SetOption153 to disable it. Berry runs in every normal build — including small 2 MiB Compact devices.
    • WebPassword exists and behaves the Tasmota way.

    Note

    A feature that is not implemented yet belongs under current gaps, not in the deliberate-differences table.

Scheduling starts as soon as the clock is valid, with no 60-second post-restart guard. Actions 0–2 route through active Power endpoints; Action 3 queues for one newmota.add_timer_handler(fn) callback. No Rules engine or blink fallback.     Berry Light object light module exposes Light state, setters and gamma helpers Global light.get()/light.set() through the Light owner, zero-based endpoint indices, and applied_power beside requested power. gamma10, reverse_gamma10 and gamma8 match Tasmota's integer curve and clamp input Implemented; timer callbacks remain open

Values travel separately through data() and are shown only as text, field values or chart numbers, so names from BLE or the network cannot become markup. Each id keeps its latest markup and data, so late viewers and several tabs see them too. Controls queue fn(name, value) for the Berry loop instead of calling the script per page request, and scripts no longer need fetch loops of their own; viewers() replaces the hint that the callback only ran while a page was open. At most 16 widgets with 4096 bytes of markup and 2816 bytes of data each; ids are A-Z a-z 0-9 _ - . (not . or ..); they are cleared with the Berry VM. The compact Beken page draws only the matrix chart and, with USE_MATTER, qr; it widens cards with w2/w3 but has no row spans and no update highlight Implemented; hardware testing pending
    Berry BLE buffer Tasmota's BLE.conn_cb(cb, buf) and BLE.adv_cb(cb, buf) take a script-allocated bytes buffer that the driver writes through a raw pointer; payloads carry a one-byte length prefix, and an advertisement is address, type, RSSI and length followed by the data The BLE module owns the buffer: BLE.buffer is a fixed-size bytes object, BLE.len the number of valid payload bytes, and BLE.init(size) picks the size (default 256, 32–4096) before the buffer first exists. conn_cb(cb), serv_cb(cb) and adv_cb(cb) take only the callback; passing a buffer raises. Payloads start at offset 0 without a length byte; for a job the script sets BLE.len before run(). An advertisement is address (6), address type (1) and signed RSSI (1), then the payload from offset 8; BLE.len counts only that payload. Active scanning is BLEActive instead of MI32Option4; BLEScan (scan timing) is new, and BLEWatch sets the watch list that BLE.adv_watch shares. BLE.info() has no peer name; its debug record adds adv_drops and the scan and connection task stack headroom to Tasmota's queue_drops. Bond records from BLE.store() are per SDK and not interchangeable with Tasmota's NimBLE structs Implemented; hardware testing pending
    Berry MQTT module Publishes strings or bytes and dispatches matching subscription callbacks across reconnects Conditionally provides import mqtt with publish, callback-based subscribe, unsubscribe and connected; bounds script filters/listeners and follows Tasmota's payload slicing. The Berry driver/mqtt_data API is not present Callback API implemented; driver delivery and hardware testing pending

Mode is reported only on ESP-IDF. BSSId, Channel and Band appear after the first link refresh, about a second after connecting. Berry reports the last collection instead of collecting first. Uptime comes from a 32-bit millisecond clock and wraps after 49.7 days. Safeboot keeps UptimeSec and the power fields Implemented; hardware testing pending
    Sleep Sleep 0..250 (default 50) sets dynamic loop sleep; SetOption60 selects normal/light sleep; SetOption127 keeps Wi-Fi awake; STATE reports Sleep, SleepMode, LoadAvg Keeps the command, default and dynamic meaning, and serves console and web input during the wait. Values above 50 are stored but act as 50 (Active reports it), so 100 ms relay timers keep their deadlines; 10 ms button probes continue. Timing-sensitive work keeps the 1 ms loop. SetOption60 1 selects normal sleep; SetOption127 1 and Sleep 0 disable Wi-Fi power saving. Pico 2 W never enables it; Beken, Bouffalo and AmebaD keep SDK defaults. STATE and StatusSTS report SleepMode, Sleep (applied) and LoadAvg, with LoadAvg in thousandths of a percent Implemented; hardware testing pending
    WifiPower Fixed dBm; 1 chip default, 0 RSSI-based; reported in Status 5. Values above 25.5 wrap, invalid text selects dynamic, dynamic mode drops to minimum without a link, and ESP32 rounds to whole dBm Keeps the command, default, limits and dynamic formula on ESP-IDF. Values above the cap are capped, invalid text is rejected, dynamic mode uses the chip default without a link, and the request reaches the SDK with quarter-dBm precision. Beken, Bouffalo, AmebaD and Pico have no command and keep SDK power Implemented on ESP-IDF; hardware testing pending
    5 GHz Wi-Fi ESP32-C5 selects 2.4 or 5 GHz automatically; Channel (36+) and Mode show the band, and WifiScan lists channels Selects the band the same way on ESP32-C5 and reports it in the same fields. BW16 uses its SDK's selection and reports Channel but not Mode. Other chips stay on 2.4 GHz Implemented on ESP32-C5 and BW16; hardware testing pending
    WifiTest and web Wi-Fi setup Both give a new network 9 s; the ESP32 core joins the first access point with that SSID it finds WifiTest is the same: 9 s (12 s on BL602, where a join with DHCP took about 7.7 s), first access point found, so with one SSID on both bands it may take 2.4 GHz. Web and recovery setup scan every channel and join the strongest access point; on ESP32-C5 they allow 30 s, because a 5 GHz join took about 24 s, and on BL602 12 s Implemented; web setup timing on hardware pending
    BLE and BLE sensors Tasmota exposes BLE through optional drivers and MI32 commands USE_BLE provides native scanning on ESP-IDF, Bouffalo, AmebaD and Pico with BLEActive, BLEScan, BLEWatch and Berry import BLE. USE_BLE_SENSORS decodes MiBeacon (encrypted v3/v5), BTHome v2 (including encrypted), Qingping CGD1 and Mi Body Composition Scale advertisements, keeps up to 32 devices, exposes at most 8 through StatusSNS/SENSOR, stores configuration in /mi32cfg, and publishes unsolicited events. ATC and PVVX formats are skipped. No Beken adapter Implemented; compile-tested, hardware testing pending
    Matter Tasmota's Matter support is target- and build-specific Optional USE_MATTER builds an on-network node from configured lights, relays and sensors on ESP-IDF and RP2350 (≥ 4 MiB flash) and on Beken (2 MiB, without MQTT). Optional USE_MATTER_BLE adds BLE commissioning; USE_MATTER_BRIDGE bridges up to seven remote Tasmota devices over MQTT; both are ESP-IDF and RP2350 only. Commands MtrInfo, MtrJoin, MtrReset; runtime switch SetOption151. Fabrics/sessions stored in /.newmota/matter/. Access-control and CASE checks currently log only; test attestation vendor 0xFFF1 Work in progress; first commissioning only
    Status aggregation Status 0 publishes separate section responses; Status0 returns the combined object on STATUS0 Over MQTT, both Status 0 and Status0 publish separate sections on STATUS, STATUS1 and so on, because the combined object does not fit the 1024-byte MQTT response limit. Elsewhere both return one combined object, and a request from elsewhere also publishes the sections while MQTT is enabled. Safeboot stays combined on STATUS0 Intentional; current dispatcher
    Status fields Status through Status 13 report the full Tasmota field lists Reports the fields with a backing setting or measurement, in Tasmota order. Status carries DeviceName; StartupUTC appears only with valid time; Sunrise/Sunset are left out on polar dates; CpuFrequency and flash identity are left out where the platform cannot report them. Safeboot keeps short sections and has no StatusMQT Implemented; remaining fields open; hardware testing pending
    Status availability Status 6 without MQTT, Status 9 without energy, Status 12 without a crash, Status 13 without shutters return an error Does the same and leaves those sections out of Status 0. Status 12 and Status 13 are always unavailable, because crash capture and shutters do not exist Implemented
    Status 4 memory units Measurements in KiB Free, Heap, StackLowMark and PsrFree in bytes; used-size and capacity fields stay in KiB. Unavailable metrics are omitted; PSRAM appears only when supported and initialized Implemented; intentional compatibility difference
    Console results Serial shows timestamped log lines with an RSL: label and topic Timestamps each result line on serial and in the Web Console (HH:MM:SS.mmm) but prints the JSON without a label. MQTT and POST /api/command stay plain JSON Implemented
    Restart reason ESP32 reset text such as Software reset digital core, or Blocked Loop Reports Power On, Software, Watchdog, Panic, Brownout, Deep Sleep or External, the same on every platform. Where the reason is unknown, Status 1 leaves it out and Info3 reports Power On or Restart. Bouffalo always counts as unknown; Safeboot Info3 keeps Power On or Restart. A blocked loop is not detected Implemented; hardware testing pending
    Boot-loop fallback From the fourth quick restart (SetOption36 offset 1), Tasmota permanently disables rules, shutters, BLE and autoexec in the settings, then clears the user GPIOs, then selects the fallback module, and switches to Safeboot after ten Newmota skips BLE, Matter, LVGL autostart and autoexec.be, and from the fifth also the user GPIO assignments, for that boot only and never changes the settings; the next boot that is not a loop starts everything again. From the tenth it restarts into the paired Newmota Safeboot only, never a foreign recovery image. Status 1 reports BootLoop. SetOption36 is absent; the fallback-module step is open. ESP32-C2 uses ordinary no-init RAM like Tasmota; power-on, brownout and deep-sleep wakes start a new count, and retention across warm-reset paths needs hardware testing. Other ESP targets require RTC memory. AmebaD uses SDK user backup register 3 with a magic and inverse count; only software and watchdog resets continue a valid count, and ten seconds of runtime clear it. Beken and Bouffalo maintain untested diagnostic no-init SRAM counts but keep the guard unavailable; they skip autoexec and never reduce a boot. Bouffalo continues valid records on unknown resets and starts fresh on deep-sleep wakes; no-init placement does not establish power-cycle freshness Implemented; hardware testing pending

    Browser language Commonly selects language behavior through firmware conventions Embeds one locale catalog at build time. Protocol names, JSON keys, MQTT topics and errors stay English Implemented

    Web transport selection May expose more than one web transport through build options Embeds one selected web representation per build and has no runtime HTTP/HTTPS fallback Design rule

    GPIO listing Can list its complete compiled GPIO name catalog GPIOs reports the choices compiled for that firmware; the complete canonical registry remains host-side Intentional size boundary

MCU Wi-Fi reset requests are acknowledged and logged rather than changing Wi-Fi settings; mode 2 does not assign pins. See TuyaMCU Compile-tested; hardware testing pending

On BP5758D an output takes the current of the channel it carries after SetOption37, as in OpenBeken. The bus is open drain with the internal pull-up, and frames are sent only when they change. More than one chip disables the Light. SM2135 keeps Tasmota's ten DAT presets; Tasmota's older Switch1 way of selecting BGR is not supported, use SM2135 DAT2 Implemented for BP5758D, BP1658CJ, SM2335 and SM2135; compile-tested, hardware testing pending
    PWM ownership SetOption15 selects raw or Light handling dynamically Freezes PWM1–PWM5 ownership and SetOption68/SetOption37 split grouping until restart, and returns an explicit ownership error for raw access to Light outputs Implemented
    PWM timing ESP32 supports target-specific and per-channel conventions Global PWMFrequency and PWMFrequency Hz,channel on all native families through checked allocation; shared timing conflicts reject without retuning siblings. Global edits clear per-output overrides. Bounds are 2–50000 Hz subject to native acceptance; invalid channels reject instead of falling back to a global edit Implemented; hardware timing untested
    Sparse Power identities Commonly packs devices into relay/light order Preserves relay identities and holes, appends Light after the highest configured relay, and rejects endpoint overflow. A sole endpoint outside index 1 retains its numbered POWER key Implemented
    Light transforms Tasmota uses subtype-specific gamma and color/fade transforms Newmota uses a bounded gamma 2.8 lookup and elapsed perceptual interpolation. As in Tasmota's calcGammaBulbCW, CT and RGBCW Lights apply gamma to the sum of both whites and share it out in their ratio, unless the whites together exceed full scale; Newmota keeps the channel ratio instead of recomputing it from CT, which matches once a fade ends. Grouped RGB and white share brightness/power unless SetOption37 bit 128 selects split endpoints on four/five-channel layouts; SetOption68 takes precedence. SetOption37 values 0–119 use Tasmota's channel permutation on PWM Lights; a value that would leave one of the Light's outputs dark keeps the default order instead of darkening it, and WS2812 strips ignore it in favour of PixelType. RGBWWTable (1–5 values 0–255; larger values are rejected where Tasmota truncates) and SetOption105 white blend apply after gamma to PWM Lights, not to independent channels or WS2812 strips; a fifth value of 0 becomes SetOption105 1 at the next restart, as in Tasmota Implemented; electrical cadence remains untested
    Light command results Light mutations can return full state; HsbColor accepts partial/indexed updates Returns bounded command values with full diagnostics in State/StatusSTS. Color1/Color2 support full-length hex, strict CSV and fixed presets. Grouped and WS2812 HsbColor accept partial/indexed updates; low-saturation queries can shift hue; achromatic queries use zero. Linked HsbColor clears white; linked White selects white and clears RGB. Split white-only edits preserve RGB state and effects Implemented; remaining Tasmota Light syntax open
    Light palettes and schemes Palettes are RAM-only and may allocate larger dynamic buffers; native animations have their own speed rules Retains up to eight palette entries and cursors through SaveData, rejects invalid lists atomically, and implements Color +/- cycling. Schemes 0–4 and Wakeup/WakeupDuration use the cooperative loop. RGB effects step every Speed × 100 ms, preserve split white outputs and use deterministic random state. Wakeup defaults to 60 s and supports 1–3000 s; queries are read-only. Unsupported persisted schemes reset to steady; numeric Color values keep fixed preset meaning even with a palette Implemented; electrical cadence untested
    WS2812 Light Configured addressable Light commands for pixel order, geometry, effects and direct pixel edits, up to 512 pixels Optional USE_WS2812 makes one configured strip the shared RGB/RGBW Light owner on ESP-IDF, Pico SDK, BL602 and AmebaD. Supports 1–512 pixels, six RGB wire orders, RGBW/white-first layouts, Led<n>, Pixels, PixelType, Rotation, Width, StepPixels, clock colors/direction and schemes 5–14. Berry may borrow that owner or open a strip on an unassigned pin. Beken does not compile these commands; DDP/Art-Net/L1MusicSync are deferred. Default PixelType is GRB Implemented; hardware testing pending
    Light defaults Subtype-specific white startup and CT defaults Initially retains RGB full-white components, white-extension components off, and CT 326; two-channel default components are both full. Configure CT explicitly for a cold/warm mix Implemented; board calibration open
    MQTT transport and integrations Capabilities depend on the selected image Bounded plain MQTT 3.1.1/QoS 0 with configurable topics, LWT, group/fallback routing, retained publications and browser configuration. TLS, Rules, sensor/button/switch producer integration, Publish3, and MQTT file/log streaming are separate work. Publications above the packet limit are skipped with a log line Plain implementation; hardware testing pending
    Discovery Publishes tasmota/discovery/<MAC>/config for its own Home Assistant integration; SetOption19 1 selects the legacy Home Assistant discovery, which standard builds leave out With USE_HA_DISCOVERY, publishes Home Assistant's own MQTT discovery, one retained homeassistant/<platform>/<MAC>/<id>/config per entity: relays, sensor readings, RSSI, Signal, Uptime, IP address and a Restart button. Needs only Home Assistant's MQTT integration; openHAB and Domoticz read the same format. No tasmota/discovery. SetOption19 1 turns it off and removes the device. Lights, switches and buttons follow. See MQTT Phase 1 implemented; hardware testing pending
    Recovery role Safeboot retains MQTT alongside its recovery surface Follows that MQTT policy on every current Wi-Fi platform, shares the paired image's persisted settings, and uses a separate small authenticated recovery page instead of the normal UI Implemented policy; native slot checks apply
    WPA3-SAE on ESP-IDF Enabled in every ESP image, with the SDK's mbedTLS supplicant Treated as a feature of images with at least 4 MiB flash. 2 MiB ESP images, including Safeboot, omit it and cannot join a WPA3-only network. On ESP chips with their own radio (ESP-IDF 5.5 and 6.1), the supplicant runs on BearSSL with the chip's SHA-1, SHA-256 and P-256 hardware (USE_WIFI_WPA3_BEARSSL, on by default), from the Newmota ESP-IDF fork. It covers WPA3-SAE, SAE-PK with P-256 keys and OWE as station, and images without HTTPS link no mbedTLS. C3, C5 and C6 Safeboot leave out SAE-PK, OWE and WPA3 SoftAP to fit their slot. On Beken (BK7231N, BK7238, BK7252N) the same backend runs under the SDK's prebuilt supplicant, on by default; SAE then offers group 19 only, where the mbedTLS backend also offered group 20. On Bouffalo (BL602, BL616, BL618DG) it is on by default, with the PSK derived on the SHA-1 engine: BL616 and BL618DG run the Wi-Fi 6 supplicant on BearSSL (group 19 only), BL602 moves only the supplicant's hashes Implemented; WPA2 tested on ESP32-C3, ESP32-S3 and XH-CB3S (BK7238), BL602 and BL616 joined a network with the BearSSL build, BL618DG untested, WPA3 on hardware pending
    Wi-Fi random numbers on Beken The BDK's prebuilt supplicant takes nonces and SAE/OWE secrets from libc rand(), which nothing seeds at boot Every Beken Wi-Fi build redirects the supplicant's os_get_random() to the hardware random number generator Implemented; builds only
    ESP-IDF assertion reporting Prebuilt Arduino libraries compile without stringified assertion text Compiles ESP-IDF with silent assertions. Every check still runs and aborts, but a failure no longer carries its expression, file and line Implemented; size boundary
    Beken recovery Image switching is not universal across boot layouts Keeps the native single-application/update model and does not claim Safeboot, local A/B rollback or Restart 3 Target-specific design

    The internal implementation also differs in ownership: portable application code uses narrow platform contracts, while SDK types, tasks, native storage and image operations stay inside platform adapters. Compatibility lives at the command, data and device-behavior edges; the internal driver and build structure is Newmota's own.

    Current gaps that are not deliberate differences¶

    These items are intended to follow Tasmota or the approved Newmota design once implementation and testing are complete:

    • TLS: HTTPS for the normal web service and TLS MQTT. The current Compact slice uses authenticated HTTP+Gzip because it is the measured implementation available today.
    • Recovery: the separate Safeboot browser updater, remote update, failed-boot handling, and platform-specific recovery testing.
    • Button debounce: ButtonDebounce supports the normal 10 ms filter and logical HIGH/LOW stability flags. The native 2 ms AC pulse detector selected by values ending in 9 remains open; those values are explicitly rejected. Cooperative probes can be delayed by blocking application work.
    • Returning to stock Tasmota remains a separate optional gate.
    • Ping: Wi-Fi applications include asynchronous IPv4 ICMP Ping; Safeboot omits it. Newmota permits one fixed campaign, uses asynchronous DNS, and accepts indices 0–8 (default one; zero tries up to four and stops at the first reply). It rejects larger indices, IPv6, whitespace and ambiguous numeric address spellings. Tasmota can keep campaigns for multiple destinations and supports IPv6 when selected. Newmota's five-second DNS deadline, one-second probe deadline/cadence, busy state through cancellation/delivery, and queryable current/last status are deliberate bounds. Results retain numeric counters on DNS failure and add an Error field. Host tests and native compilation do not establish device reachability.
    • Additional drivers and commands whose platform owners do not yet exist.
    • Audio consumers: TensorFlow microphone integration, camera/audio synchronization, simultaneous network walkie-talkie routing and BLE audio endpoints. The native session API supports bounded microphone capture, encoded files/network streams and configurable I2S input/output, but these higher-level consumers have no Newmota owners.
    • Berry Light timer callbacks; light.get()/light.set() cover retained endpoint state and synchronous mutations, and the gamma helpers provide pure integer conversions.
    • Matter follow-up: access-control/CASE enforcement, production attestation, MtrUpdate, and testing beyond a first commissioning.
    • Module2 and other unfinished compatibility edges.
    • Further MQTT features: Home Assistant discovery for lights, switches and buttons, Rules, and MQTT file/log streaming.
    • Stock Tasmota-to-Newmota OTA migration: a bootstrap settings importer is present in ESP32 source for all eight ESP targets; end-to-end device trials remain open. See Switching From Tasmota.

    Berry filesystem listings¶

    Berry path.listdir() returns direct-child basenames with a deliberate limit of 128 entries and 8192 bytes of names per call. Exceeding either limit raises value_error without returning a partial listing. Paths use the shared filesystem limit of 191 bytes and reject embedded NUL bytes.
