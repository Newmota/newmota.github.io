    Personal Build Configurations¶

    Newmota allows developers and power users to define custom, local build environments without modifying checked-in repository files. Personal configurations live under user_config/ and are ignored by git.

    Tip

    make config writes this file for you from a menu; see Build Your Firmware. This page covers editing it by hand, including the fields the menu does not set (crypto, idf_version, native, solidify, filesystem). The menu keeps these fields when it reopens the file.

    Defining a Personal Configuration¶

    Create a YAML file in user_config/<custom-id>.yaml that inherits from any checked-in application environment:

    # user_config/my-c2-plug.yaml
name: my-c2-plug
inherit: esp32c2-2m
language: de_DE
crypto: none

    Another example enabling the full crypto test suite on an ESP32-S3:

    # user_config/s3-crypto-full.yaml
name: s3-crypto-full
inherit: esp32s3-qio-opi
profile: Standard
crypto: all

    Allowed Overrides¶

    To maintain layout integrity and device safety, personal configurations can only override specific explicit fields:

    Field Description Values / Examples
    inherit Required. The checked-in base application environment ID. esp32c2-2m, esp32s3-qio-qspi, pico2-w, pico-w, cb2s-2m, etc.
    profile Firmware resource profile budget. Compact, Standard, Large
    language Build-time browser locale catalog (one per firmware, no runtime switch). en_GB, de_DE (from language/); en is an alias for en_GB
    features Optional compiled driver features (merges by key). Map of booleans such as USE_BME280, USE_BH1750, USE_TC74, USE_DHT, USE_I2C, USE_WS2812, USE_I2S, USE_DISPLAY, USE_DISPLAY_QSPI, USE_UNIVERSAL_TOUCH, USE_LVGL, USE_WEB_HTTPS, USE_BLE, USE_BLE_SENSORS, USE_MATTER, USE_GPS, RTC chips, and the energy drivers. See below.
    crypto BearSSL and Berry crypto feature selection. all, none, or a mapping with berry and primitives
    idf_version Pinned ESP-IDF SDK track (ESP targets only). "5.5" (default) or "6.1"
    native Platform-specific native SDK build flags or overrides. Map of vendor-specific SDK key-values
    solidify Berry driver classes built into flash instead of uploaded. List of driver files, such as berry/drivers/camera/ov2640.be. See below.
    filesystem Files written into the factory filesystem image. List of file paths, or mappings with source and target. See below.

    Immutable Base Properties

    Chip architecture, target board recipe, partition layout, Safeboot companion pairing, and role are inherited directly from the checked-in base environment and cannot be overridden. This ensures that flashing offsets, memory maps, and bootloader requirements remain valid.

    Built-in Berry Drivers¶

    solidify lists Berry driver files whose classes the build puts into flash, so no upload is needed and the classes take no heap. Only the classes a file marks with #@ solidify:<Class> are built in; nothing runs at startup. autoexec.be still creates and registers them, which lets one firmware carry competing drivers and each board pick its own:

    name: eye-cam
inherit: esp32s3-qio-opi-8m-8m
features:
  USE_WEBCAM: true
solidify:
  - berry/drivers/camera/ov2640.be

    # autoexec.be
cam.register(OV2640())

    Paths are relative to the firmware repository; files of your own can live in user_config/. List every file a class needs, bases first: segment_display.be before tm1637.be. The build refuses a file whose #@ requires: features are off, a class whose base is missing or listed later, and code other than classes at a file's top level. A file loaded at runtime replaces a built-in class of the same name, so a fixed driver can be tried without a rebuild.

    Files in the Factory Filesystem¶

    filesystem lists files the build writes into the factory LittleFS image. A path lands at /<file name>; a mapping with source and target puts it elsewhere or renames it:

    filesystem:
  - berry/drivers/camera/ov2640.be            # lands at /ov2640.be
  - source: berry/drivers/camera/isp/ov5647.json
    target: /isp.json
  - source: user_config/eye-cam-autoexec.be
    target: /autoexec.be

    Note

    Only a factory flash writes these files; OTA updates and Safeboot never touch the filesystem. They are defaults: after the first boot they belong to you and may be edited or deleted.

    The build refuses a file that is also in solidify, two entries with one target, targets inside /.newmota or /sd, .be files whose #@ requires: features are off, and files that do not fit the factory filesystem. solidify and filesystem append to the inherited lists.

    Optional Features¶

    Select optional modules with a boolean features mapping. Dependencies are selected automatically; setting a dependency to false while selecting a feature that needs it is an error, as are unknown names and features that the platform, role, or flash size does not support. Optional features are application-only (the paired Safeboot keeps its own selection), and the resolved selection is written to build/work/<environment>/config/feature_map.json.

    name: workshop-c2
inherit: esp32c2-2m
features:
  USE_BH1750: true
  USE_TC74: true
    Feature Default Notes
    USE_I2C, I2C sensors (USE_BH1750, USE_TC74, USE_BME280), USE_DHT Off Sensors
    USE_BLE, USE_BLE_SENSORS Off Bluetooth & BLE Sensors; ESP-IDF, Bouffalo, AmebaD and Pico only. No checked-in profile selects them
    USE_MATTER, USE_MATTER_BLE, USE_MATTER_BRIDGE Off Matter; ESP-IDF and RP2350 with at least 4 MiB flash, or Beken (2 MiB, without MQTT; USE_MATTER_BLE and USE_MATTER_BRIDGE are ESP-IDF and RP2350 only). No checked-in profile selects them
    USE_GPS Off Optional GPS; UBX only, all families except BL616/BL618DG
    RTC chips (USE_DS3231, USE_DS1307, USE_BM8563, USE_PCF85063, USE_PCF85363, USE_RV3028, USE_RX8010, USE_RX8025, USE_RX8130) Off Optional RTC Chips
    USE_HA_DISCOVERY Off Home Assistant discovery; selects USE_MQTT. Enabled in the test environments while it is measured
    USE_NTP_SERVER Off Optional NTP Server
    Energy drivers (USE_PZEM004T, USE_MODBUS_ENERGY, …) Off Energy Metering
    USE_I2S, USE_AUDIO_MP3, USE_AUDIO_AAC, USE_AUDIO_OPUS Off At least 4 MiB flash; not on Beken or BL602
    USE_DISPLAY, USE_UNIVERSAL_TOUCH, USE_DISPLAY_QSPI, USE_LVGL Off Displays & Touch; QSPI on ESP-IDF, BL616/BL618DG, and Pico only
    USE_WS2812 Off Not on Beken
    USE_WEB_HTTPS On for Large Off for Compact, Standard, and Safeboot
    USE_WIFI_WPA3_BEARSSL On for ESP chips with their own radio and at least 4 MiB flash (ESP-IDF 5.5 and 6.1), for BK7231N, BK7238 and BK7252N, and for Bouffalo BL602, BL616 and BL618DG Wi-Fi supplicant on BearSSL instead of mbedTLS, application and Safeboot. Not on ESP-Hosted chips (P4, P4X), whose companion runs the supplicant. With it off, C5, C6 and C61 Safeboot drop WPA3 to fit their slot. On Beken the prebuilt supplicant then runs on BearSSL, SAE with group 19 only, and images without HTTPS link no mbedTLS (about 22.9 KB smaller); BK7231T and BK7252, whose supplicant brings its own wolfSSL crypto, reject it. On Bouffalo, BL616 and BL618DG run the Wi-Fi 6 supplicant on BearSSL (SAE group 19 only); BL602 moves only the supplicant's hashes and keeps SAE on the SDK's blcrypto_suite. Bouffalo images without HTTPS then link no mbedTLS (application 20.8 KB smaller on BL616, 16.4 KB on BL602)
    USE_CRYPTO_HW_SHA1, USE_CRYPTO_HW_SHA256, USE_CRYPTO_HW_P256 On with USE_WIFI_WPA3_BEARSSL, where the chip has the engine BearSSL on the ESP and Bouffalo hardware engines; on Bouffalo, USE_CRYPTO_HW_SHA1 also derives the Wi-Fi PSK on the SHA engine. ESP32 has no usable SHA engine; ESP32-C2 has no P-256 engine
    USE_SERIAL, USE_DEVICE_SPI, USE_ADC, USE_MODBUS_RTU Off Shared hardware owners, selected automatically by drivers that need them

    The complete list, with dependencies and platform limits, is OPTIONAL_FEATURES in tools/newmota/features.py in the firmware repository.

    Crypto defaults¶

    crypto is a compile-time choice that does not affect HTTPS. When omitted, ESP Standard and Large applications include the Matter crypto APIs plus SHA256, AES_GCM, MD5, and random; other applications include SHA256, MD5, and random; Safeboot includes none. A build that requests random fails if the platform has no entropy source.

    Mutable Settings Belong on the Device¶

    Build-time configuration is reserved for compile-time properties (such as crypto algorithms or language packs). Do not attempt to embed Wi-Fi credentials or hardware pinouts in YAML files:

    • Wi-Fi, MQTT, DeviceName, OtaUrl: Configure via serial console commands or the device-hosted Web UI.
    • GPIO / Module / Template: Configure using Module, Template, or GPIO commands.

    Building Personal Environments¶

    Personal environments integrate seamlessly into the make workflow:

    # Check catalog and view personal environments
make list

# Validate personal configs alongside repository catalog
make validate-catalog

# Build the personal environment
make my-c2-plug

# Or using explicit ENV syntax
make build ENV=my-c2-plug

# Flash to device
make flash ENV=my-c2-plug

    make all and the automated test matrix (make test) deliberately build only checked-in catalog environments, keeping personal builds strictly local.
