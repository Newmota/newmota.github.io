    Development Setup¶

    Newmota uses a dual-level environment strategy: Python tooling is managed locally with uv, while platform cross-compiler toolchains and native SDKs are maintained under user tool directories (~/.espressif and ~/.newmota/tools/).

    Python Environment (uv)¶

    The project uses uv for fast, deterministic Python environment management.

    # Create and synchronize .venv
make uv-setup

    The pyproject.toml pins the host dependencies, including: - littlefs-python == 0.18.0: Host-side LittleFS filesystem image generation and manifest verification. - pyserial == 3.5: Wired serial communication and flashing adapters. - pyyaml >= 6.0: Catalog and environment configuration parsing. - blflashcommand (Git-pinned Staars/blflashcommand) and bflb-fw-post-proc == 1.4.5: Bouffalo flashing and image post-processing. - bk7231tools == 2.1.2: Beken probing, backup, and flashing. - brotli, zopfli: build-time web asset compression (Brotli for HTTPS builds, Gzip for HTTP builds).

    The dev extra adds ruff (Python lint, settings in pyproject.toml) and the pinned clang-format used by make format-cpp. Use uv run --locked --extra dev ruff check tools to check the Python tooling.

    Toolchain & SDK Directories¶

    Platform toolchains and SDK assets are kept separate from the repository source code and the Python .venv.

    Platform Toolchain Location Environment Variables
    ESP-IDF ~/.espressif IDF_TOOLS_PATH
    Raspberry Pi ~/.newmota/tools/arm-none-eabi/ & ~/.newmota/tools/pico-sdk/ NEWMOTA_TOOLS_PATH
    Bouffalo Pinned native XuanTie release + ~/.newmota/tools/bouffalo/<version>/ NEWMOTA_TOOLS_PATH
    Beken ~/.newmota/tools/arm-none-eabi/ NEWMOTA_TOOLS_PATH
    AmebaD ~/.newmota/tools/amebad/<version>/ NEWMOTA_TOOLS_PATH

    Host Python Isolation¶

    Native SDK installers (especially ESP-IDF) invoke a host Python interpreter outside Newmota's .venv. This design ensures that ESP-IDF's internal virtual environments (~/.espressif/python_env/) remain independent of Newmota's development environment.

    To override the host Python interpreter if necessary:

    make setup ENV=esp32c2-2m SDK_PYTHON=/usr/local/bin/python3

    SDK installers need a host Python 3.10 or newer outside the project virtual environment.

    Apple Silicon Bouffalo note¶

    On Apple Silicon, Bouffalo setup downloads the pinned native Xuantie GCC 14 release with its host dependencies included; a separate Homebrew runtime-library install is not required. Bouffalo flashing uses the pinned blflashcommand Python package, so no Rosetta is needed.

    SDK Pinning & Release Archives¶

    Every SDK is pinned to one commit of a Newmota fork. Builds download a stripped, checksummed release archive of that commit from Newmota/sdk-archives and extract it read-only into ~/.newmota/sdk/ (NEWMOTA_SDK_PATH moves it). No Git submodules are needed, and only the SDKs a build uses are downloaded.

    • ESP-IDF v5.5.5 from the Newmota/esp-idf fork, branch newmota/v5.5.5 (the tag plus the external Wi-Fi crypto that WPA3 on BearSSL needs), with esptool 4.14.0.
    • ESP-IDF v6.1 from the same fork, branch newmota/v6.1 (the tag plus the same change), with esptool 5.3.1. make setup PLATFORM=esp prepares both tracks.
    • Pico SDK v2.3.1 from Newmota/pico-sdk (the upstream release, unpatched).
    • BouffaloSDK v2.3.34 from Newmota/bouffalo_sdk.
    • Beken BDK v3.0.78 from Newmota/framework-beken-bdk.
    • Realtek AmebaD snapshot 2026-06-18-newmota.4 from Newmota/ameba-rtos-d.

    make sdk-fetch downloads every archive in advance for offline builds. For SDK patch work, make sdk-checkout SDK=<key> clones the pinned commit into .sdk/<source> (ignored by Git); while that checkout exists, builds use it instead of the archive.

    Human-readable SDK version declarations live under config/sdk/:

    config/sdk/
├── esp-idf.toml
├── esp-idf-v6.1.toml
├── esp-idf-v5.5.constraints.txt
├── esp-idf-v6.1.constraints.txt
├── pico-sdk.toml
├── bouffalo.toml
├── beken.toml
└── amebad.toml

    Before running builds, Newmota checks that the installed SDK matches its pin in config/sdk/<platform>.toml: the archive checksum and its recorded commit, or the commit of a .sdk/ checkout. Run make sdk-check at any time to verify every installed SDK.

    Compiler Acceleration (ccache)¶

    If ccache is installed on your host system and available in PATH, Newmota's native platform build adapters automatically integrate it into cross-compiler invocations.

    # Verify ccache availability
which ccache

    No additional configuration is necessary; missing ccache falls back smoothly to normal compilation without failure.
