    Build From Source¶

    Contributor reference for compiling Newmota: environment, board catalog, toolchains, test matrices and build variables. To configure and build an image for your own device, start with Build Your Firmware.

    Prerequisites¶

    • macOS or Linux host system.
    • Python 3.10+ installed.
    • uv package manager installed (uv installation guide).
    • Standard build utilities: make, git, and optionally ccache for build acceleration.

    1. Setup Environment¶

    Initialize the project Python environment managed by uv:

    make uv-setup

    This creates the isolated .venv directory and installs the lockfile-pinned helper tools (pyserial, littlefs-python, pyyaml, bk7231tools, blflashcommand, and more).

    2. Inspect the Catalog¶

    Inspect configured hardware targets, environment files, and board recipes:

    # List all configured chips, boards, and environments
make list

# Open the menuconfig/configurator for a personal build
make config

    Validate the complete declarative catalog without compiling firmware or installing heavy platform SDKs:

    make validate-catalog

    3. Toolchain & SDK Setup¶

    Platform toolchains and native SDK dependencies can be installed explicitly or fetched lazily on first build.

    # Install tools for a specific target environment
make setup ENV=esp32c2-2m

# Or install all tools for an entire platform cohort
make setup PLATFORM=esp
make setup PLATFORM=bouffalo
make setup PLATFORM=beken
make setup PLATFORM=amebad
make setup PLATFORM=pico
make setup PLATFORM=all

# Verify the installed SDKs against config/sdk/*.toml
make sdk-check

    Note

    Toolchains are installed outside the project tree (e.g. ~/.espressif for ESP-IDF and ~/.newmota/tools/ for other platforms) using host Python interpreters to prevent virtualenv contamination.

    4. Building Firmware¶

    Build an individual environment:

    # Build the baseline ESP32-C2 2 MiB environment
make esp32c2-2m

# Or build the Raspberry Pi Pico 2 W environment
make pico2-w

# Or using the explicit build target form
make build ENV=esp32c2-2m

    Build any target board recipe on demand, independently of the test matrix:

    make esp32s3-qio-opi

    Board recipes are also generated Make targets. ESP-IDF has an environment for every board recipe, so make all builds the complete ESP-IDF set while make test remains the five-entry routine matrix. Direct board builds resolve the same-named environment when one exists and run lazy SDK setup.

    Build the checked-in cross-platform test matrix defined in config/env/matrices/test.txt (4 Compact 2 MiB environments + 1 Standard 4 MiB Pico 2 W target: esp32c2-2m, bl602-2m, cb2s-2m, bw16-2m, pico2-w):

    make test

    Run host tests and primitive cryptographic known-answer suites:

    make test-host

    Build all configured environments (this takes a very long time; the routine check is make test):

    make all JOBS=8

    Build variables¶

    Variable Effect
    JOBS=<n> Parallel jobs; default is every logical CPU. Beken's Make-based build always uses one.
    VERBOSE=1 Shows native compiler commands and full SDK output (NEWMOTA_VERBOSE=1 for the CLI).
    SDK_LOG_LEVEL=<level> Vendor SDK log level: none, error, warn (default), info, debug, verbose.

    Native SDK work goes to build/work/<environment>/; packages with their manifest go to build/firmware/<environment>/<version>/. Pico builds also write a UF2 below build/work/<environment>/native/. make format-cpp formats the first-party C/C++ sources with the pinned formatter (make format-check-cpp checks), and make clangd ENV=<env> writes a compilation database for editors.

    5. Personal Configurations¶

    You can create local, custom build definitions without modifying checked-in files by creating user_config/<custom-id>.yaml and inheriting from an existing environment. Build your custom environment with:

    make <custom-id>

    See Personal Build Configurations for full details on supported overrides (profile, language, crypto, native).
