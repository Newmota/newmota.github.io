    Beken Devices¶

    Newmota on Beken ARM Wi-Fi microcontrollers — the chips inside countless Tuya modules (CB2S, CB3S, CBU, WB2S, XH-CB3S). One warning up front: on Beken an update can erase your stored files, keeping only Wi-Fi credentials — see Files & Settings.

    Supported Microcontrollers¶

    • BK7231N (Primary non-ESP Compact target; QFN32 2 MiB/4 MiB) — environments cb2s-2m, cb3s
    • BK7238 (distinct SoC profile) — environment xh-cb3s (do not use cb3s for XH-CB3S hardware)
    • BK7231T — environment wb2s; generic Tuya QFN32 board recipe also available.
    • BK7252 / BK7252N — generic-bk7252-2m, generic-bk7252-4m, generic-bk7252n-2m, and generic-bk7252n-4m, for the Beken SDK bootloader.
    • BK7231Q / BK7251 — board recipes are present; use a matching target profile.

    Native Build & Toolchain¶

    The platform adapter (tools/newmota/platforms/beken/build.py, with specialist helpers bdk.py, codec.py, profile.py) drives the BDK Make-based pipeline over the pinned framework-beken-bdk v3.0.78 (the Newmota/framework-beken-bdk fork; Newmota's own sources build with -Wall):

    • Integrates native chip defaults (config/build/beken/<target>/defconfig) with the resolved SoC profile.
    • Compiles C++ code (src/app/core/) alongside Beken platform bindings (src/platform/beken/), including the native LittleFS adapter (filesystem.cpp), flash access layer (flash_access.cpp), OTA-critical settings bridge (critical_settings.cpp, net_param_tlv.cpp), and BDK compatibility shims (native/bdk_compat.c, native/libc_heap.c, native/libc_syscalls.c). Standard output and error go to the log UART.
    • Produces a native AXF/raw diagnostic image, a CRC-wrapped application RBL for wired flashing, and an OpenBeken-style compressed/encrypted RBL for single-image OTA staging.
    # Build the baseline BK7231N CB2S environment
make cb2s-2m

# Build the BK7238 XH-CB3S environment
make xh-cb3s

    The Beken and AmebaD Make-based builds record their real cross-compiler invocations for clangd and may compile/relink the staged native project to obtain them. No platform substitutes a host compiler.

    Storage Model¶

    Beken uses a bounded OpenBeken-style LittleFS tail overlay inside the native OTA staging envelope (config/partitions/beken/2m.toml, 2m-bk7238.toml, 4m.toml). OTA may erase that filesystem — this overlap is deliberate.

    The portable OTA-critical record keeps both Wi-Fi slots outside that overlay through an opaque Beken NET-parameter adapter (net_param_tlv.cpp), which preserves co-resident native records. Retention across OTA remains untested. Settings otherwise live in the LittleFS overlay; there is no Newmota Safeboot or alternate-image package on Beken — Safeboot support is intentionally deferred, and recovery scope is stock OTA plus physical/ROM recovery.

    Runtime Console¶

    Beken uses the SDK's selected log UART for both logs and commands: UART1 on the current BK7231N and BK7238 BDK profiles. Newmota polls the SDK's interrupt-fed software receive FIFO; command parsing and execution stay in the common serial transport. When TuyaMCU uses UART1, the serial console is unavailable. Typed characters are not echoed — enter a command such as Status followed by Enter.

    The BK7238/XH-CB3S path has passed initial command-input hardware smoke testing; other exact-board combinations and other consoles have not yet been tested.

    Wired Operations¶

    The pinned bk7231tools writer (v2.1.2, device support) handles chip/flash probing, complete backup, aligned write/verify, and chip reboot. Upload runs at 1500000 baud and the console at 115200 (override with BAUD/MONITOR_BAUD).

    flash, flash-monitor, and both flash-only forms install fresh Newmota configuration: they initialize LittleFS and remove Newmota's Wi-Fi credentials from the NET records. Native NET vendor records are retained, and foreign non-TLV configuration is replaced with an empty native table. A damaged native table or too little credential space stops the operation before any write. The bootloader, RF calibration, device identity, and BLE bonding are preserved. A package built before this policy existed must be rebuilt.

    # Beken: use the module's UART1/download pins for the programmer.
# The first operation must be a complete backup; this preserves the stock
# bootloader and metadata.
make probe ENV=cb2s-2m PORT=/dev/cu.usbserial-0001
make backup ENV=cb2s-2m PORT=/dev/cu.usbserial-0001 OUTPUT=cb2s-stock.bin
make flash ENV=cb2s-2m PORT=/dev/cu.usbserial-0001

# XH-CB3S/BK7238 uses its own exact environment; do not use `cb3s` for it.
make probe ENV=xh-cb3s PORT=/dev/cu.usbserial-0001
make backup ENV=xh-cb3s PORT=/dev/cu.usbserial-0001 OUTPUT=xh-cb3s-stock.bin
make flash ENV=xh-cb3s PORT=/dev/cu.usbserial-0001

# Beken development update: writes only stock OTA staging and may erase the LittleFS tail.
make update ENV=cb2s-2m PORT=/dev/cu.usbserial-0001
make update ENV=xh-cb3s PORT=/dev/cu.usbserial-0001

    Web & Network Services¶

    BK7231N and BK7238 environments compile the device-hosted HTTP web service and bounded plain MQTT client:

    • Compact Beken Web Page: Beken embeds one smaller, English-only root page rather than the full generic UI. It has the same sidebar, responsive panels, and four themes, with Home (light cards with colour wheel, dimmer and white/CT slider, one switch per relay no light owns, and energy cards), Configuration tabs (Wi-Fi, MQTT, Module, Template, Timers), Information and a filesystem browser with LittleFS used/free/total, a console, and the native RBL updater. Firmware update requests are sent in 1 KiB chunks and verified before activation. Updating requires acknowledging that LittleFS data may be lost.
    • Onboarding AP: Boots an open newmota-XXXXXX SoftAP (192.168.4.1) when unconfigured, allowing network setup and credential testing from any browser.
    • No BLE Adapter: Newmota does not drive the Beken Bluetooth LE radio. USE_BLE and USE_BLE_SENSORS are unavailable on BK7231 targets, so no BLE sensors are decoded here.
    • MQTT & Telemetry: Full Tasmota-compatible MQTT client and periodic telemetry reports over plain IPv4 TCP.
    • Feature limits: Beken does not compile WS2812 (its pinned DMA waveform path could violate the WS2812B LOW limit), I2S audio, or QSPI displays, and its native SPI display selectors are rejected; software SPI, I2C, EPD, and GPIO I80 displays work where the module exposes enough pads.

    Hardware testing¶

    The XH-CB3S/BK7238 path has passed hardware testing for its core stack: stable boot/restart, UART1 commands, LittleFS mount/read, Wi-Fi station association, DHCP, NTP synchronization, full HTTP web UI, web console, and Wi-Fi onboarding handoff.

    Still open: update retention, complete backup/recovery, filesystem survival across OTA, GPIO topology, and repeated power-loss behavior — plus equivalent testing on the other Beken boards. What each wired operation writes is described in Build System Internals.
