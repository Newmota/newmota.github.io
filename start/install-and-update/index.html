    Install & Update Firmware¶

    This page gets Newmota onto your hardware: a backup of the original firmware first, the first install over a USB/serial cable or from the browser, updates later on, and watching the device boot. If your device already runs Newmota and you just want to use it, skip to First Steps.

    No firmware yet? Build it first. Moving a device from Tasmota? See Switching From Tasmota.

    1. Back Up First¶

    Before the first install, read the device's whole flash into a file. With it you can put the original firmware back later.

    # Show the connected chip, its security state, flash identity and size.
make probe ENV=esp32c2-2m

# Save the whole flash. Existing files are never replaced.
make backup ENV=esp32c2-2m PORT=/dev/cu.usbserial-0001 OUTPUT=backup.bin

    Keep the backup outside build/firmware/. On AmebaD, probe and backup are not available yet.

    2. First Install¶

    From the browser¶

    The Web Flasher writes a factory package from the browser, without a build environment: load newmota-<environment>-<version>-factory.zip from the build directory, connect the device and write. It writes the same regions and refuses the same cases as make flash-only, backs up the whole flash first (on by default), and opens a serial monitor afterwards. It covers Beken, Bouffalo, AmebaD, the ESP32 family and the Raspberry Pi Pico (RP2040 and RP2350, over USB in BOOTSEL mode), in a desktop Chromium browser.

    Over a cable¶

    # Build, package, probe, flash, verify and reset.
make flash ENV=esp32c2-2m

# The same, then open the serial console.
make flash-monitor ENV=esp32c2-2m

    Every flash command checks the package manifest and its hashes before it opens the device.

    Choosing the port: with one USB/serial adapter connected, it is picked automatically. With several, a menu opens (arrow keys; r refreshes the list), before the long build starts. PORT=/dev/cu.usbserial-0001 sets it directly, for scripts.

    make flash ENV=esp32c3-4m PORT=/dev/cu.usbserial-0001

    A device with more flash than the package gets a larger filesystem; a smaller one is refused. ESP32-S3 boards use the chip's built-in USB port, the ser variants UART0. See ESP32 Devices.

    # Connect the programmer to the module's UART1/download pins.
make backup ENV=cb2s-2m PORT=/dev/cu.usbserial-0001 OUTPUT=cb2s-stock.bin
make flash ENV=cb2s-2m PORT=/dev/cu.usbserial-0001

# XH-CB3S (BK7238) has its own environment; do not use cb3s for it.
make backup ENV=xh-cb3s PORT=/dev/cu.usbserial-0001 OUTPUT=xh-cb3s-stock.bin
make flash ENV=xh-cb3s PORT=/dev/cu.usbserial-0001

    The first operation must be the complete backup: it keeps the original bootloader and metadata. A flash starts with fresh Newmota settings; RF calibration and device identity are kept. Beken has no Newmota Safeboot; recovery means a stock OTA or a wired flash.

    Tested so far: the XH-CB3S core stack. Update retention and recovery are open. Details

    make backup ENV=bl602-2m PORT=/dev/cu.usbserial-0001 OUTPUT=bl602-stock.bin
make flash ENV=bl602-2m PORT=/dev/cu.usbserial-0001

    Tested so far: factory write and boot on BL602. Storage, the browser UI, recovery and updates are open; BL618DG is untested. Details

    make backup ENV=pico2-w PORT=/dev/cu.usbserial-0001 OUTPUT=pico2w-stock.bin
make flash ENV=pico2-w PORT=/dev/cu.usbserial-0001

    The board must be in BOOTSEL mode. A running Newmota image usually switches to it by itself; otherwise hold BOOTSEL while connecting.

    Tested so far: a Pico 2 W smoke test. Backup/restore and recovery are open. Details

    # Enter UART download mode when prompted, then reset the board
# by hand after verification.
make flash ENV=bw16-2m PORT=/dev/cu.usbserial-0001

    Tested so far: factory write, storage and Wi-Fi on BW16. Updates and recovery are open. Details

    3. Updating¶

    Over the network¶

    Set the address of an image on your network, then start the update:

    > OtaUrl http://192.168.1.10:8000/firmware.bin
{"OtaUrl":"http://192.168.1.10:8000/firmware.bin"}

> Upgrade 1
{"Upgrade":"Downloading"}

> Upgrade
{"Upgrade":"Active","Bytes":524288,"Total":1048576}

    Upgrade 1 loads the image over plain HTTP from a server that sends its length; HTTPS, redirects and chunked transfers are refused. Upgrade shows the progress.

    In the browser:

    • Firmware Update page (normal web UI): shows the running version and build. "Update from URL" saves OtaUrl and starts Upgrade 1, polling Upgrade once a second while the page is open and an update is active (platforms that download inside Safeboot report the handoff and restart). The update-channel card has no backend yet and stays visibly unavailable.
    • Safeboot Recovery Web: On ESP-IDF, Bouffalo, AmebaD, and Pico targets, type Restart 3 on the console to boot into the dedicated Safeboot recovery image. Navigate to http://<device-ip>/ to access the authenticated recovery page and upload a new application image chunk-by-chunk directly from your browser. The normal web UI's Firmware Update page does the same handoff for you: "Upload firmware file" runs Restart 3 and then shows the recovery page. Safeboot requires a configured WebPassword and refuses access without it, so the page warns when none is set.
    • Beken Dedicated Web Updater: On BK7231N and BK7238 targets, normal application firmware embeds a compact root page containing device status, console, LittleFS browser, and a native RBL updater.

    A device that was switched from Tasmota over the air keeps Tasmota's Safeboot; see Switching From Tasmota.

    Over a cable¶

    make update ENV=esp32c2-2m

    make update is the quick cycle while you tinker: it rebuilds and writes only the application. The bootloader, Safeboot and your files and settings stay as they are; on Bouffalo, Pico and AmebaD a device that is in Safeboot stays there. On Beken it writes the stock OTA area, which overlaps the filesystem, so your files may be erased (Wi-Fi credentials are kept). On AmebaD, enter UART download mode when prompted and reset by hand afterwards. On Pico, the board must be in BOOTSEL mode.

    make update is not the signed remote update. What it writes on each platform is described in Build System Internals.

    4. Watching the Device¶

    make monitor ENV=esp32c2-2m

    MONITOR_PORT selects a different logging UART for the two -monitor commands; MONITOR_BAUD overrides its speed. BAUD overrides programming speed (or monitor speed for standalone make monitor). On Beken the runtime console is UART1 (see Beken devices); typed characters are not echoed.

    Default speeds:

    Platform Upload baud Console baud
    AmebaD 230400 115200
    Beken 1500000 115200
    Bouffalo 500000 2000000
    ESP-IDF, Pico SDK Programmer default 115200

    Command Reference¶

    Command Action
    make probe ENV=<env> Inspects connected chip identity, flash ID, security state, and physical flash capacity.
    make backup ENV=<env> OUTPUT=backup.bin Reads full physical flash memory and saves a raw recovery backup outside build/firmware/. Existing files are never replaced.
    make flash ENV=<env> Builds, packages, probes, flashes, verifies, and resets the target device.
    make update ENV=<env> Short wired dev cycle: rebuilds and writes only the application region (see below).
    make flash-only PACKAGE=<path> Flashes an existing development factory package manifest without compiling code.
    make monitor ENV=<env> Opens interactive serial console monitor.
    make flash-monitor ENV=<env> Flashes device and automatically connects serial monitor with post-flash reset.
    make flash-only-monitor PACKAGE=<path> Flashes an existing package, then connects the monitor.

    make flash-only writes an existing package without building:

    make flash-only PACKAGE=build/firmware/esp32c2-2m/<version>/manifest.json
make flash-only-monitor PACKAGE=build/firmware/esp32c2-2m/<version>/manifest.json
