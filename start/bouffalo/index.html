    Bouffalo Devices¶

    Newmota targets Bouffalo Lab RISC-V microcontrollers with the pinned BouffaloSDK v2.3.34 (the Newmota/bouffalo_sdk fork, which carries the Wi-Fi 6 and warning fixes Newmota needs).

    Supported Microcontrollers¶

    Environment Chip Flash Profile
    bl602-2m BL602 (RISC-V Wi-Fi 4 + BLE) 2 MiB Compact
    bl602-4m BL602 4 MiB Standard
    bl616dk BL616 (Wi-Fi 6) 4 MiB Standard
    bl618dgdk BL618DG (Wi-Fi 6, single-core) 4 MiB Standard

    Each application environment is paired with its own Safeboot image. BL702 is cataloged as planned and has no Newmota native build adapter.

    BL618DG is low priority. It builds and is packaged with the code it shares with BL616, but is not tested on hardware and gets no BL618DG-specific features.

    Note

    BL618 modules. bl618dgdk targets the BL618DG chip only. Modules such as the Ai-M61-32S are BL616-family silicon: use bl616dk and a GPIO template. The earlier bl618dk environment was renamed bl618dgdk.

    Native Build Lifecycle¶

    The Bouffalo platform adapter (tools/newmota/platforms/bouffalo/build.py) invokes BouffaloSDK's CMake build system and linker scripts. Partition maps are selected by SDK target: 2m.toml for the BL602 Compact layout, and 4m-bl602.toml, 4m-bl616.toml, or 4m-bl618dg.toml for the 4 MiB targets. Each application build also builds its paired Safeboot image and packages the layout.

    make bl602-2m
make bl602-4m
make bl616dk
make bl618dgdk

    BL616 and BL618DG use the SDK's FHOST Wi-Fi 6 manager with FreeRTOS and lwIP. Both are Standard applications with the paired Safeboot, and their setup AP is served from 192.168.4.1 with DHCP, like every other family. SDK logging is forced to none in the BL602, BL616, and BL618DG Safeboot images so they fit their recovery partitions.

    Apple Silicon toolchain note¶

    Bouffalo setup downloads the pinned native Xuantie GCC 14 release from Newmota/bouffalo-toolchain-macos-arm64. Its macOS binaries include their host dependencies; a separate Homebrew runtime-library install is not required. Device operations use the pinned blflashcommand Python package (installed by make uv-setup), so Apple Silicon needs no Rosetta.

    BL602 2 MiB Layout¶

    Region Offset Size Content
    Boot2 0x000000 0x00E000 Bootloader
    Partition tables 0x00E000 / 0x00F000 — Redundant CRC-protected copies
    Application (FW slot 0) 0x010000 0x14C000 Normal firmware
    Safeboot (FW slot 1) 0x15C000 0x094000 Recovery image
    LittleFS (lfs) 0x1F0000 0x010000 (64 KiB) Persistent filesystem region

    The Compact layout contains only the regions Newmota owns: it omits the SDK's unused manufacturing, media, PSM, key, and factory regions so the application gets the contiguous space in front of Safeboot. Restart 3 flips the active slot through a CRC-protected partition-table update, which is safe across interruption.

    Four MiB Layouts¶

    BL602, BL616, and BL618DG each have a target-specific map. All reserve the final 320 KiB for LittleFS:

    Region BL602 4 MiB BL616 / BL618DG 4 MiB Content
    Boot2 0x000000 – 0x00E000 0x000000 – 0x00E000 Bootloader
    Partition tables 0x00E000 / 0x00F000 0x00E000 / 0x00F000 Redundant CRC-protected copies
    Application (FW slot 0) 0x010000, size 0x2A0000 0x010000, size 0x260000 Standard firmware
    Safeboot (FW slot 1) 0x2B0000, size 0x100000 0x270000, size 0x140000 Recovery image
    LittleFS (lfs) 0x3B0000, size 0x050000 0x3B0000, size 0x050000 Persistent filesystem (320 KiB)

    The BL602 hardware trial did not make LittleFS or settings available, so these regions are layout budgets, not hardware-tested storage capacity. A device carrying an older layout needs a complete factory package before application-only updates are accepted.

    Wired Operations¶

    make probe ENV=bl602-2m PORT=/dev/cu.usbserial-0001
make backup ENV=bl602-2m PORT=/dev/cu.usbserial-0001 OUTPUT=bl602-stock.bin
make flash ENV=bl602-2m PORT=/dev/cu.usbserial-0001
make update ENV=bl602-2m PORT=/dev/cu.usbserial-0001
    • Upload runs at 500000 baud by default; the console runs at 2000000 baud on UART0 (override with BAUD and MONITOR_BAUD).
    • Writes are verified by the loader's SHA-256 check. probe validates both partition-table copies (one valid copy is accepted) and cannot tell a BL616 from a BL618: the environment selects the chip profile.
    • backup reads the declared flash size.
    • update writes only the application slot; boot2, both partition-table copies, Safeboot, vendor regions, and LittleFS are untouched, and the FW active index is preserved, so a device in Safeboot stays there.

    Wi-Fi Supplicant on BearSSL¶

    USE_WIFI_WPA3_BEARSSL is on by default in every Bouffalo Wi-Fi build (BL602, BL616, BL618DG), together with USE_CRYPTO_HW_SHA1. To go back to the SDK's mbedTLS supplicant, turn it off in a personal build:

    name: bl616dk-mbedtls
inherit: bl616dk
features:
  USE_WIFI_WPA3_BEARSSL: false
    • BL616 and BL618DG: the Wi-Fi 6 supplicant runs on BearSSL instead of mbedTLS, WPA3-SAE included. SAE offers group 19 (P-256) only; an access point that allows only groups 20 or 21 cannot be joined.
    • BL602: only the supplicant's MD5, SHA-1 and SHA-256 move to BearSSL; SAE stays on the SDK's own crypto.
    • The Wi-Fi key (PSK) is derived on the chip's SHA-1 engine: 4096 PBKDF2 iterations take 48.5 ms on BL616 and 63.5 ms on BL602.
    • Without HTTPS the image links no mbedTLS. Application images are 16,400 B smaller on BL602 (bl602-2m) and 20,800 B on BL616 (bl616dk); Safeboot images are 11,376 B smaller on BL602, 13,424 B on BL616 and 14,928 B on BL618DG.
    • BL602 and BL616 joined a network with it; BL618DG is untested on hardware.
    • Please report: after joining a WPA3 network with a BL616 build that has this option, the console shows a line like WIF: supplicant stack free 6144 of 12288 B (the first number varies). Please send that line, with the access point's WPA3 mode (WPA3-only or WPA2/WPA3 transition), once the Newmota issue tracker opens in the alpha stage. It tells us whether the supplicant's 12 KiB stack is large enough; the line will be removed once there is a report.

    Peripheral Limits¶

    Feature BL602 BL616 BL618DG
    PWM Yes (GPIO n → channel n % 5) Yes, PWM-v2 (GPIO n → channel n % 4, one shared carrier) Unavailable
    WS2812 strip Yes Unavailable Unavailable
    I2S audio No peripheral Unavailable Unavailable
    ADC, auxiliary UART, native display SPI Native display SPI0 available Unavailable Unavailable
    Display (USE_DISPLAY_QSPI) Rejected Yes Yes (signal order provisional)

    Two PWM pins that map to the same channel cannot run together, because the channels share one divider and period. General GPIO display transports stay available on every Bouffalo chip.

    Ready-Made Templates¶

    Templates for the Ai-Thinker Ai-M61-32S-Kit, Ai-M62-12F-Kit, and Ai-WB2-12F-Kit (RGB indicator on PWM pins, driven as a dimmable RGB light) are in the firmware repository's TEMPLATE.md. Test one with Color FF0000 or Dimmer 20.

    Hardware testing¶

    The attached BL602 board passed a factory write with device read-back and booted to its setup AP and HTTP listener; the boot console still reported WEB: HTTPS identity or server start failed on the BL602 4 MiB adapter. Probe/backup testing, LittleFS/settings, browser UI, Safeboot recovery, and application-only updates remain open. BL602 and BL616 joined a network with the standard build, which has the BearSSL supplicant; BL618DG has compile/package evidence only.
