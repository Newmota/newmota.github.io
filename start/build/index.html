    Build Your Firmware¶

    Newmota has no ready-made downloads yet, so the first step is to build an image for your device on your own computer. You don't need to edit code for this: make config lets you pick your chip and features from a menu, checks that the combination works, and then builds it.

    Wi-Fi, MQTT, GPIO templates and other device settings are not part of the image. You set them later on the device, through the web interface or console commands, as in Tasmota. New terms such as environment or profile are explained in the Glossary.

    Coming from Tasmota?

    Tasmota offers ready-made binaries for most devices and tailored builds through user_config_override.h. In Newmota, the interactive make config takes the place of both: choose a starting environment, switch features on or off, and build.

    What you need¶

    • A macOS or Linux computer.
    • Python 3.10 or newer, git and make.
    • uv, the Python package manager (installation guide).

    Get the source and set up the project's Python environment:

    git clone https://github.com/Newmota/Newmota.git
cd Newmota
make uv-setup

    You don't need to install any compilers or vendor SDKs yourself. The first build for a platform downloads and installs its toolchain and SDK, which takes a while. Later builds reuse them.

    Find your environment¶

    An environment is a checked-in build target: chip, flash size, profile and the board's layout. Supported Devices and the platform guides name the environment for each board. To see the full list:

    make list

    To use an environment exactly as it is, you can skip make config and build it straight away, for example make esp32c3-4m.

    Configure with make config¶

    make config                    # choose everything from the menu
make config ENV=esp32c3-4m     # start from this environment

    The configurator runs in the terminal and has four tabs:

    Tab What you do there
    Target Choose the platform family, then the chip and the environment to start from. Set the profile, the language and the name of your build.
    Features Switch optional features on or off, such as sensors, displays, BLE or Matter. / filters the list.
    Summary Preview the file that will be written.
    Help Keys and markers.

    Each feature shows why it is on or off:

    Marker Meaning
    [*] You selected it.
    [=] The base environment already has it.
    [+] A feature you selected needs it, so it is on as well.
    [ ] Off.
    [-] Not available on this target; the detail line says why.

    Selecting a feature brings in its dependencies, and features that your chip, flash size or board cannot support are blocked. Problems therefore show up while you choose, not halfway through a long build.

    Press w to write the configuration, or b to write it and build it right away. q quits and asks first if you have unsaved changes.

    Your build is saved as user_config/<name>.yaml, a short file that git ignores:

    # User build configuration written by `make config`.
# Build it with: make build ENV=my-c3
name: my-c3
inherit: esp32c3-4m
features:
  USE_BME280: true
# Selected automatically through dependencies: USE_I2C

    To change it later, run make config ENV=my-c3. Settings the menu doesn't offer, such as built-in Berry drivers or files for the factory filesystem, can be added to the file by hand and are kept when you reopen it. See Personal Build Configurations.

    Without the menu¶

    The same steps work from a script or another tool:

    # Show every feature and its state for an environment
uv run python tools/menuconfig.py --env esp32c3-4m --list-features

# Write user_config/my-c3.yaml with a BME280 sensor
uv run python tools/menuconfig.py --env esp32c3-4m --enable USE_BME280 --name my-c3 --write

# Build it
uv run python tools/menuconfig.py --env my-c3 --build

    Build¶

    make my-c3

    make build ENV=my-c3 does the same. Checked-in environments build the same way, for example make esp32c3-4m.

    The finished package lands in build/firmware/<environment>/<version>/. It contains the manifest that make flash uses and the newmota-<environment>-<version>-factory.zip that you can load into the Web Flasher.
