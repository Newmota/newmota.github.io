    Bluetooth & BLE Sensors¶

    Newmota can scan Bluetooth Low Energy advertisements, run Berry scripts as a BLE client or peripheral, and decode common environmental and security sensors without a hub. BLE is optional, off by default, and not yet hardware-tested: the native backends compile on ESP-IDF, Bouffalo, AmebaD and Pico, while Beken does not provide a BLE adapter.

    Scope

    BLE here means Bluetooth Low Energy only. Classic Bluetooth, BLE audio, extended/periodic advertising, coded PHY and BLE Mesh are outside the current adapters.

    Enabling BLE¶

    No checked-in environment or Safeboot selects BLE. Switch it on in make config, or add it to a personal build configuration by hand:

    name: my-ble-gateway
inherit: esp32s3-qio-qspi
features:
  USE_BLE: true

    Selecting USE_BLE does not enlarge any partition or establish a minimum flash size. Each image must still fit its own catalog slot. With BLE in the firmware, SetOption115 1 starts the stack and SetOption115 0 stops it (the option defaults to 1 when the feature is present).

    Platform notes:

    Platform Status
    ESP-IDF NimBLE host; the reference implementation.
    Pico W / Pico 2 W Pico SDK BTstack over the CYW43 radio; build the pico-w or pico2-w environment.
    Bouffalo BL602 / BL616 Native SDK blestack. BL618DG's BLE is deferred; BL618 modules use BL616. BL602 and BL616 are compile-tested only.
    AmebaD BW16 Realtek btgap.a. The controller shares Wi-Fi calibration, so the Wi-Fi radio must be up.
    Beken BK7231 No BLE adapter.

    All adapters expose legacy scanning, advertising and scan responses with up to 62 report bytes, one report slot, eight watched addresses, and one total connection shared between client and peripheral roles. Extended advertising, controller privacy and BLE Mesh are not available. Check radio operation, Wi-Fi coexistence, runtime heap headroom, pairing and bonding, and OTA coexistence on your board.

    Scan Commands¶

    Scanning is passive by default, with a 100 ms interval and an 80 ms window. Three commands change it until reboot; nothing is saved, so repeat them from autoexec.be with newmota.cmd() if you need them every start.

    Command Effect
    BLEActive 0\|1 Passive (default) or active scanning. Active scanning requests scan responses and appends them to the report after a brief wait.
    BLEScan <interval>,<window> Scan timing in milliseconds, 3 to 640, with the window no longer than the interval.
    BLEWatch <MAC>[,<type>] Adds a 12-hex-digit device (colons optional) to the watch list. Address type is 0–3, default 0. BLEWatch 0 empties the list; BLEWatch lists it. Once the list holds a device, only watched devices are reported.

    Bouffalo and AmebaD accept address types 0 and 1 only. Duplicate filtering is disabled on every backend, so reports arrive at the scan interval. Dropped reports are counted in BLE.info().

    > BLEActive 1
{"BLEActive":1}

> BLEScan 200,150
{"BLEScan":{"Interval":200,"Window":150}}

> BLEWatch AA:BB:CC:DD:EE:FF,0
{"BLEWatch":[{"MAC":"AABBCCDDEEFF","Type":0}]}

    Berry BLE¶

    import BLE provides the staged Berry interface: init, loop, info, conn_cb, serv_cb, adv_cb, adv_watch, set_MAC, set_svc, set_chr, run and store. The module owns BLE.buffer; set BLE.len to the input length before run. Unlike Tasmota, conn_cb(cb), serv_cb(cb) and adv_cb(cb) take only the callback, payloads carry no length byte, and an advertisement is the address (6 bytes), address type and signed RSSI followed by the payload from offset 8, with BLE.len counting the payload. Completion callbacks run from the cooperative application loop.

    Advertisement and connection callbacks share the buffer. Advertisements wait while a job owns it. When a native consumer such as a sensor decoder also scans, it sees every report first and the script receives one held copy; reports arriving while that copy waits count in adv_drops.

    Typical uses are reading a custom GATT sensor, exposing a small local service, or filtering advertisements. The adapter details differ per backend; see the platform notes above and treat the Berry BLE API as staged rather than portable.

    BLE Sensors¶

    USE_BLE_SENSORS adds native decoding for common advertisements while BLE runs (SetOption115 1). It depends on USE_BLE and is available on ESP-IDF, Bouffalo, AmebaD and Pico.

    features:
  USE_BLE: true
  USE_BLE_SENSORS: true

    Decoded formats and devices¶

    • Xiaomi MiBeacon 0xFE95, including encrypted v3 and v5 frames.
    • BTHome v2 0xFCD2, including encrypted frames.
    • Qingping CGD1 0xFDCD.
    • Mi Body Composition Scale (MIBCS).

    Supported MiBeacon types include Flora, MJ_HT_V1, LYWSD02, LYWSD03, CGG1, CGD1, NLIGHT, MJYD2S, YLYK01, MHOC401, MHOC303, MCCGQ02, SJWS01L, YLKG07/08 and YLAI003. The ATC (0x0A1C) and PVVX (0x944A) custom formats are not decoded; switch those thermometers to BTHome in their firmware settings.

    BTHome v2 decodes temperature, humidity, battery, illuminance, moisture, conductivity, mass, pressure, voltage, current, power, energy, CO₂, TVOC, PM2.5, PM10, distance, counts, UV index, the binary sensors (Opening, Door, Motion, Window, Smoke and others, as 0/1), and Button<n> / Dimmer<n> events. Other objects are skipped. A second object of the same kind is numbered, such as Temperature2 or Voltage2.

    Encrypted BTHome needs the device key from MI32Key or /mi32cfg. A packet whose counter does not increase is ignored; once a device has a key, its plaintext packets are ignored.

    Device registry and output¶

    • Up to 32 devices are retained. The dashboard shows all of them.
    • At most 8 reach StatusSNS and MQTT SENSOR: configured devices first, then the most recently seen. A log line counts the rest, and devices that would not fit the 1024-byte message are left out with their own log line, so local sensors and energy values keep their place.
    • A device unseen for one hour is not shown, and each value is omitted one hour after its last update.
    • Each device reports its decoded fields plus RSSI, Time (local time of its last packet in seconds, omitted until the clock is set) and MAC. LastSeen (seconds) appears only in the dashboard.
    • Remote temperatures never become the global temperature.

    Configuration commands¶

    The commands keep their Tasmota names and the /mi32cfg file format, so a Tasmota file loads unchanged. ATC and PVVX entries are skipped with a log line.

    Command Effect
    MI32Key <key><MAC> Sets a 16-byte bind key (44 hex digits; the 36-digit YLKG07/08 form is accepted).
    MI32Name<n> <text> Names device slot n (0-based; default 1). Empty text clears it.
    MI32Cfg Writes all devices, keys and names to /mi32cfg.
    MI32Option0 Always aggregate every value in event messages (default 1).
    MI32Option1 Keep BLE devices out of StatusSNS and MQTT SENSOR; the dashboard still shows them.
    MI32Option2 Direct bridge: publish an event message for every new value or sighting.
    MI32Option3 Stop admitting new devices; set automatically when /mi32cfg has entries.
    MI32Option5 Generic sightings: any public address, or a random address resolved by an IRK stored as the key of a PID 0000 entry. Set automatically by such an entry.

    Options last until reboot. Active scanning (BLEActive 1) is needed to receive device names.

    Event messages¶

    Events publish immediately on tele/<topic>/SENSOR as {"<device>":{...}}, one device per message, like Tasmota's triggered telemetry but without Time, matching the periodic SENSOR message.

    Buttons (Button<n>), knob turns (Dimmer, Dimmer_P), holds (Hold), motion and its end (Motion, Events), door changes, leaks, no-motion time, and the scale's stable weight, impedance or ImpedanceFailed trigger a message. With MI32Option2, every new value or sighting does. A message carries the changed fields, or all held values with MI32Option0, plus RSSI and MAC; a sighting adds its raw Payload. A message the MQTT queue cannot take is retried — a sighting with its next report — and dropped after 10 seconds.

    History¶

    Every BLE reading also appears in the 24-hour sensor history, in the card's units and with its offsets, including samples taken before a setting changed. History is kept in RAM and starts empty after a restart. Ages (LastSeen, NMT) are stored as presence: 1 for a period in which the age was below one minute, so a device's visibility over the day shows at a glance. Dew point is derived and is not recorded.

    Testing¶

    The BLE adapters are native compile-tested. Radio operation, pairing and bond round trips, dense advertising, notification pressure, VM restart, runtime RAM headroom, Wi-Fi coexistence, flash writes and OTA still need hardware testing. Select BLE only in a personal build you can test.
