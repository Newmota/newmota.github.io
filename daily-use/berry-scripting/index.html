    Berry Scripting¶

    Berry is Newmota's tiny automation language: one-liners on the console (Br) and a startup script (/autoexec.be) that runs at every boot. It works in every normal build, including small 2 MiB devices — only the minimal Safeboot recovery image leaves it out.

    Note

    Berry here is the same language Tasmota uses, so Tasmota Berry examples largely apply. What Berry can reach (commands, hardware) is still growing — when in doubt, the console command it wraps is the same one you'd type yourself.

    Where Berry runs¶

    Berry is compiled into every normal application build on every chip family (2 MiB Compact included) and left out only of Safeboot recovery images, which have no room for a scripting engine.

    Interactive Command (Berry / Br)¶

    The console processor exposes the Br (or Berry) command to evaluate expressions and run statements:

    > Br 1 + 2
{"Br":"3"}

> Br for i: 0..3 print(i) end
{"Br":"nil"}

    Safety & Execution Deadlines¶

    To prevent runaway scripts or infinite loops from hanging the microcontroller:

    1. Heartbeat Watchdog Hook: The VM installs an execution observer (BE_OBS_VM_HEARTBEAT) that monitors CPU run time.
    2. 4-Second Execution Deadline: Any single script execution exceeding 4000 ms is automatically interrupted, raising an exception: 
      {"Br":"timeout_error: Berry code running for too long"}
    3. Protected Calls (pcall): Script evaluation and result string conversion are executed within a protected context. Exceptions leave the Berry VM clean without leaking allocated stack frames.

    Log Routing & Logging¶

    Berry's built-in print() function is connected directly to Newmota's central logging facility, routing script output to serial consoles and Web/Berry console histories. In addition, Tasmota-compatible log(message, level) writes directly to log sinks at the specified log level:

    print("Hello from Berry on Newmota!")
log("Warning condition detected", 2)

    The device keeps the last 8 lines of Berry output for the console. A console error report takes at most 7 of them — the error message first, then the traceback — and ends with (traceback truncated, full trace in the log) when it is longer, so a long traceback never hides its error. The log keeps every line.

    Global Host Objects¶

    newmota — Commands, Timers, Cron & Utilities¶

    Newmota exposes the global newmota object (matching Tasmota's tasmota object pattern) with built-in methods for commands, scheduling, and system info:

    # Run a command and inspect structured results
var result = newmota.cmd("Power1 on")
print("Relay state:", result["POWER1"])

# Run a quiet command
var net = newmota.cmd("_Status 5")
print("IP:", net["StatusNET"]["IPAddress"])

# Run command chains
var multi = newmota.cmd("Power1 on; Dimmer 50")

# Millisecond timers and scheduling
var now = newmota.millis()
if newmota.time_reached(now + 1000)
  print("One second passed")
end

# Non-blocking timers (shares 16 callback slots with cron and defer)
newmota.set_timer(2000, def () print("Fired after 2 seconds") end, "my_timer")
newmota.remove_timer("my_timer")

# Cooperative delay and execution yield
newmota.delay(10)  # Sleep 0..50 ms cooperatively
newmota.yield()    # Yield to RTOS / network tasks

# Time, formatting & cron
var epoch = newmota.rtc()
var time_dict = newmota.time_dump(epoch)
var formatted = newmota.strftime("%Y-%m-%d %H:%M:%S", epoch)

# Local-time cron recurrence (six fields: sec min hour day-of-month month day-of-week)
newmota.add_cron("0 */15 * * * *", def () print("Quarter-hour tick") end, "cron_15m")
newmota.remove_cron("cron_15m")

# Wi-Fi status
var wifi = newmota.wifi()
print("Wi-Fi Quality:", wifi["quality"], "IP:", wifi["ip"])

# Trigger manual garbage collection
newmota.gc()

    light — Hardware Light Control & Gamma¶

    When Light support is compiled and configured (SetOption15 1), Berry exposes the global light object for owner-backed control:

    # Read state of Light endpoint 0
var st = light.get(0)
print("Power:", st["power"], "Applied:", st["applied_power"])
print("Brightness:", st["bri"], "Color Temperature:", st["ct"])

# Synchronous state update
light.set(0, {"power": true, "bri": 75, "ct": 320})

# Set RGB color
light.set(0, {"rgb": [255, 0, 128]})

# Pure-integer gamma helpers
var g10 = light.gamma10(512)
var g8 = light.gamma8(128)

    Global Classes¶

    Pixel Framebuffers (pixmat)¶

    The global pixmat class provides high-speed native framebuffers for 2D matrices and strip layouts independently of display or strip hardware: - Formats: 1 byte (grayscale), 2 bytes (packed), 3 bytes (RGB 0xRRGGBB), or 4 bytes (RGBW 0xRRGGBBWW). - Constructors: pixmat(width, height, bpp[, serpentine]), pixmat(bytes_buf, width, height, bpp), or pixmat(bitplane, bytes_per_line). - Methods: get(x, y), set(x, y, color[, bri]), clear([byte]), blit(source, dx, dy), blit(packed_glyph_bits, ...), scroll(direction), buffer(), deinit().

    WS2812 LED Strips (led_strip)¶

    Construct standalone addressable strips or borrow the configured Light strip: 

    s = led_strip(4, 30, "GRB")
s.set(0, 0x00FF00)  # Green
s.show()
s.close()

    Display Controller (display())¶

    When compiled with USE_DISPLAY: true, Berry exposes the global display() class bound to the panel defined in /display.ini: - Methods: width(), height(), pixel(x, y, color), fill_rect(x, y, w, h, color), refresh(), power(on), invert(on), rotation(0..3), brightness(0..255).

    Audio sessions¶

    With USE_I2S, Berry can play, record and analyze audio through import audio and audio.Session. See Audio for setup and session lifecycle.

    Berry drivers and commands¶

    With the default-off USE_BERRY_DRIVERS feature, Berry scripts do the jobs of Tasmota Rules the way Tasmota's Berry drivers and commands do. newmota.add_driver(obj) registers any instance, without a limit; newmota.remove_driver(obj) removes it. For each event Newmota looks up the method name on every driver, in registration order, as Tasmota does: a class method or any member that holds a function, also one assigned after add_driver(). It calls the function as f(obj, cmd, idx, payload, raw) with raw nil; cmd and payload are empty strings except for audio. Berry ignores unused arguments. Adding a driver twice does nothing. The global Driver class is Tasmota's: an instance with one variable per hook, so d = Driver(), d.every_second = def (self) ... end and newmota.add_driver(d) work in any order.

    Method When idx
    every_50ms, every_100ms, every_250ms, every_second Scheduler ticks 0
    any_key Each button or switch key, as Tasmota's SendKey device_save<<24 \| key<<16 \| state<<8 \| device, key 0 button, 1 switch, state Tasmota's POWER_* code
    switch_action Newmota extension: each detached SetOption114 switch Action, which Tasmota shows only to Rules Same packing as any_key, key 1
    button_pressed Debounced press or release count<<24 \| level<<16 \| last_level<<8 \| index, level 0 pressed, zero-based index
    button_multi_pressed Completed one to five presses; not a SetOption13 immediate press count<<8 \| index
    set_power_handler Each Power command, interlock step or group write, changed or not, as Tasmota's SetDevicePower Bit mask of all Power states after it, bit 0 Power1
    network_up, network_down Station or Ethernet address gained or lost 0
    audio With USE_I2S: an I2S direction starts, changes its rate or stops. cmd "rate" comes first on a start or rate change, then "power"; payload is "tx" or "rx" The sample rate for rate; 1 on start, 0 on stop for power

    As in Tasmota, a method that returns true ends that event's dispatch: the drivers after it do not see it. A driver removed during dispatch shifts the later ones, so the next one misses that event, also as in Tasmota. Unlike Tasmota, the hooks only observe: native button, switch and Power actions always happen. Detach inputs with SetOption73 1 (buttons) or SetOption114 1 (switches) to handle them in Berry alone. Hooks run in the Berry poll after the event, never inside it, so a command a hook issues produces its own events in a later poll. A Light change without a Power command, such as Dimmer 0, also calls set_power_handler once the Power mask changes. Up to 40 input and Power events wait for the poll, enough for Power0 on 32 outputs; more are dropped with a log warning. Unlike Tasmota, a tick method (every_50ms to every_second) assigned after add_driver() starts within a second, so drivers without tick methods do not run the Berry poll on every tick. An exception in one driver is logged and does not stop the others. A hook that runs into the 4 s Berry deadline is aborted and ends the poll; the drivers after it miss that event. Sensor values, schedules and MQTT topics use the existing APIs; there is no Rules engine and no trigger syntax.

    newmota.add_cmd(name, f) adds a command, as Tasmota's tasmota.add_cmd(). It runs only when no native command has the name, from any source (console, web, MQTT, newmota.cmd()), and matches the name without regard to case and without a trailing index. Newmota calls f(name, idx, payload, payload_json) with the name as registered, the index (1 without one), the payload string (empty without one) and json.load(payload), nil when it is not JSON. f must be a function or closure; a method raises, as in Tasmota. Adding a name again replaces its function; newmota.remove_cmd(name) removes the exact name. The function answers with one of newmota.resp_cmnd_done(), resp_cmnd_error(), resp_cmnd_failed() ({"<Name>":"Done"}, "Error", "Failed"), resp_cmnd_str(text) ({"<Name>":"<text>"}) or resp_cmnd(json) (the JSON as given); the last call wins. Without one the command answers nothing. A command that raises is logged and still answers with what it set before. A response longer than 1024 bytes fails the command. Driver.add_cmd(name, f) registers f(self, name, idx, payload, payload_json) for that driver.

    class Follow
  # Power2 follows Power1.
  def set_power_handler(cmd, idx)
    var want = (idx & 1) != 0
    if want != ((idx & 2) != 0)
      newmota.cmd(want ? "Power2 ON" : "Power2 OFF")
    end
  end
  # With SetOption114 1, Switch1 toggles Power3 (state 2 is TOGGLE).
  def switch_action(cmd, idx)
    if (idx & 0xFF) == 1 && ((idx >> 8) & 0xFF) == 2
      newmota.cmd("Power3 TOGGLE")
    end
  end
end
newmota.add_driver(Follow())

    var d = Driver()
d.every_second = def (self) log("tick") end
d.add_cmd("Greet", def (self, cmd, idx, payload) newmota.resp_cmnd_str("Hello " + payload) end)
newmota.add_driver(d)
# Greet World  ->  {"Greet":"Hello World"}

    newmota.read_sensors() returns the MQTT SENSOR document as a string, as Tasmota's tasmota.read_sensors() does, for json.load(). It holds the switch states, sensors and energy fields with StatusSNS units and precision, without Tasmota's Time. It returns nil when there is nothing to report or the document exceeds the 1024-byte MQTT payload. Tasmota's optional display argument is accepted and ignored. A thermostat with hysteresis:

    import json
class Thermostat
  var target, band, heating
  def init() self.target = 21.0 self.band = 0.5 self.heating = nil end
  def every_second()
    var raw = newmota.read_sensors()
    var s = raw != nil ? json.load(raw) : nil
    var t = s != nil && s.find("DS18B20") != nil ? s["DS18B20"].find("Temperature") : nil
    if t == nil return end
    var heat = self.heating
    if t < self.target - self.band heat = true end
    if t > self.target + self.band heat = false end
    if heat != nil && heat != self.heating     # switch only on a change
      self.heating = heat
      newmota.cmd(heat ? "Power1 ON" : "Power1 OFF")
    end
  end
end
newmota.add_driver(Thermostat())

    Standard Berry Modules¶

    Digital GPIO (import gpio)¶

    Directly read and control unassigned digital GPIO pins, or inspect configured functions: 

    import gpio

# Check configured function assignments (e.g. Relays)
var pin = gpio.pin(gpio.REL1)
var used = gpio.pin_used(gpio.REL1)

# Configure unassigned pin as digital output
gpio.pin_mode(12, gpio.OUTPUT)
gpio.digital_write(12, gpio.HIGH)

# Read digital input level
gpio.pin_mode(14, gpio.PULLUP)
var level = gpio.digital_read(14)

# PWM on an unassigned pin or the template's Buzzer pin: 440 Hz at 50% duty (0..1023)
var buzzer = gpio.pin(gpio.BUZZER)
gpio.set_pwm_freq(buzzer, 440)
gpio.set_pwm(buzzer, 512)

    set_pwm and set_pwm_freq follow Tasmota; a PWM phase is not supported. The firmware's examples/audio/rtttl.be plays RTTTL ringtones on a buzzer, or with Rtttl("i2s") on the I2S output (USE_BERRY_AUDIO), with the command Rtttl <song>.

    Hardware Serial Ports (import serial)¶

    Access native hardware UART ports with optional RS-485 direction control (DE): 

    import serial

# Open UART with RX=16, TX=17 at 115200 baud
u = serial(16, 17, 115200)

# Optional: configure RS-485 driver enable pin
u.config_tx_en(4)

# Write data
u.write("STATUS\r\n")

# Non-blocking read of staged bytes
if u.available() > 0
  var data = u.read()
  print("Received:", data)
end

u.close()

    Persistent Data Storage (import persist)¶

    Stores dynamic script attributes safely in /_persist.json. Serialized data is bounded to 8192 bytes and 16 container levels, and saved atomically: 

    import persist

persist.my_counter = persist.find("my_counter", 0) + 1
persist.device_label = "Living Room Sensor"

# In-place mutations to lists/maps require dirty() before save
persist.dirty()

# Saves dirty attributes immediately to LittleFS (also flushed before restart)
persist.save()

    Filesystem Navigation (import path)¶

    Inspect and manage files on the LittleFS partition: 

    import path

if path.exists("/display.ini")
  print("Display descriptor found")
end

# List direct children (bounded to 128 entries and 8192 bytes)
var files = path.listdir("/")
print("Files:", files)

path.remove("/temp.txt")
path.rename("/old.txt", "/new.txt")

    MQTT Scripting (import mqtt)¶

    Publish messages and subscribe to topics with script callbacks across broker reconnects: 

    import mqtt

if mqtt.connected()
  mqtt.publish("tele/mydevice/alert", "motion detected")
end

# Subscribe with callback handler
mqtt.subscribe("cmnd/mydevice/custom", def (topic, payload)
  print("Received MQTT command:", topic, payload)
end)

    Energy Meters (import energy)¶

    With USE_BERRY_ENERGY_API (checked access to selected meter drivers) or USE_BERRY_ENERGY (a virtual meter fed by your script), import energy exposes the configured meter slots. Handles validate an identity generation on every access, so a removed or replaced instance needs a new handle:

    import energy
var meter = energy.configure(1, 3)       # virtual meter in slot 1, 1–8 channels (durable)
meter.voltage = 230.0                    # volts
meter.current = 1.25                     # amps
meter.active_power = 287.5               # watts (negative = export)
meter.active_power_phases[1] = 120.0     # zero-based channel 2
print(meter.read())                      # copied map of all measurements

    Hardware measurements are read-only; configure hardware meters with the normal energy commands. Scalars address channel 1, _2…_N suffixes or _phases views address the rest. Optional API flags add read-only Today/Yesterday projections and balanced sums.

    Dashboard Widgets (import widget)¶

    With Berry and the web interface, import widget puts cards on the Home page. As with Tasmota's MI32.widget(), the script ships the card's HTML (and, if it wants, its JS); the page adds base code so most widgets need only short markup and no JS. Unlike Tasmota, the markup is set once and the values travel separately as data, which the page shows only as text.

    import widget
widget.set("garage", '<div class="w2"><h3>Garage</h3>'
  '<p><span class="value" data-v="temp"></span><span class="unit">°C</span></p>'
  '<div data-chart="line" data-v="history" data-grid></div>'
  '<button data-act="open">Open</button></div>')
widget.data("garage", {"temp": 21.5, "history": [20.1, 20.4, nil, 21.5]})
widget.on("garage", def (name, value) print(name, value) end)
widget.remove("garage")   # true when it existed
    • widget.set(id, html [, order]) creates a widget or replaces its markup; its data stays. The id is 1–31 characters of A-Z a-z 0-9 _ - ., but not . or ... order (integer) sorts widgets, equal orders keep registration order; without it a new widget gets 0 and an existing one keeps its place.
    • widget.data(id, value) replaces the data of an existing widget with json.dump(value).
    • widget.on(id, fn) sets the callback for an existing widget's controls; widget.on(id, nil) removes it. It runs on the Berry loop as fn(name, value), both strings. An exception is logged; the widget and callback stay.
    • widget.viewers() is true while a page has asked for widget updates within the last three seconds, so a script can skip work nobody sees.
    • Markup is trusted, data is not. Text from elsewhere (BLE names, MQTT payloads) belongs in data(), never in set().

    What the page provides for the markup:

    Markup Effect
    Root element Becomes the card; w2, w3, h2, h3 span grid columns and rows. Tasmota's <div class="box w2 h2"> works as it is
    data-v="key" Shows data[key] as text, an input's or select's value, or a checkbox's state; "a.b" reaches into nested maps. A field being edited is left alone
    data-chart with data-v line (numbers, lists of numbers, or {"values", "color"} series), hist, gauge (a number, or a map with value, min, max, unit, stops), qr, matrix; options data-grid, data-min, data-max, data-height, data-labels, data-color, data-unit, data-stops, data-size
    data-act="name" A click sends "", a checkbox "true"/"false", a field its value (at most 63 bytes)
    <input type="checkbox" class="toggle"> in a <label> Drawn as the page's switch; a <button> without a class gets the page's button style
    Classes value, unit, label, small, row, scroll; h2–h4 are card titles; tables, inputs and selects are styled

    A <script> in the markup runs each time the markup is set, and again after a page reload or a device restart, so wrap it in (() => { ... })();. It can use nm.on(id, fn) (called as fn(data, card) after every data update), nm.send(id, name, value), nm.card(id), nm.line, nm.hist, nm.gauge, nm.qr and nm.rows(tbody, rows) (text-only table cells). Scope its CSS to [data-id="<id>"].

    Limits: 16 widgets, markup at most 4096 bytes and data at most 2816 bytes of JSON per widget, otherwise set or data raises value_error. Up to eight control actions wait for the Berry loop. Widgets live in RAM and are cleared with the Berry VM. The compact Beken page shows the same markup, data and controls, but its only charts are matrix and, with USE_MATTER, qr; w2/w3 widen a card there, row spans and the update highlight are left out.

    The examples in examples/widget/ port Tasmota's dashboard scripts. The web API is /api/widgets/updates/<since>, /api/widgets/markup/<id> and POST /api/widgets/action. See the Web Interface.

    Bluetooth (import BLE)¶

    When USE_BLE is selected, import BLE exposes the staged BLE interface: init, loop, info, conn_cb, serv_cb, adv_cb, adv_watch, set_MAC, set_svc, set_chr, run and store. The module owns BLE.buffer; set BLE.len to the input length before run. Completion callbacks run from the cooperative loop. See Bluetooth & BLE Sensors.

    Matter (_matter)¶

    With USE_MATTER, Berry can drive the commissioning window, bridge and access-control policy. The API is intentionally small:

    Br print(_matter.pairing_code())
Br _matter.open_basic_window(900)          # seconds
Br _matter.bridge.discover(true)           # with USE_MATTER_BRIDGE
Br print(_matter.bridge.discovered.keys())
Br _matter.set_enforce_access(true)        # survives restarts

    See Matter for commissioning, bridged devices and the current access-control limitations.

    Embedded LVGL GUI (import lv)¶

    When compiled with USE_LVGL: true and a /display.ini panel descriptor, Berry includes the full LVGL 9.6.0 engine: 

    import lv

# Initialize LVGL (if SetOption135 1 suppressed auto-start)
lv.start()

# Create a button on active screen
var btn = lv.button(lv.screen_active())
lv.obj_set_size(btn, 100, 40)
var label = lv.label(btn)
lv.label_set_text(label, "Click Me")
    Embedded fonts include montserrat (10, 14, 20, 28), seg7 (8..48), unscii (8, 16), and icons (10..28). Specialized widgets lv.clock_icon() and lv.wifi_arcs_icon() provide built-in status indicators.

    Berry Cryptography Module (crypto)¶

    In builds with crypto enabled (Standard ESP32 builds, crypto: all, or custom user_config), Newmota provides the BearSSL-backed crypto module with Tasmota-compatible APIs:

    import crypto

# SHA-256 Hashing
var hash = crypto.SHA256()
hash.update("Newmota")
var digest = hash.finish()

# HMAC-SHA256
var hmac = crypto.HMAC_SHA256("my-secret-key")
hmac.update("payload")
var mac = hmac.finish()

# Random Bytes (requires platform entropy)
var bytes = crypto.random(16)

    Supported primitives and classes: - Symmetric Ciphers: AES_CBC, AES_CCM, AES_CTR, AES_GCM, CHACHA20_POLY1305 - Elliptic Curves & Signatures: EC_C25519 (X25519), EC_P256 (ECDSA / RFC 6979), ED25519, RSA - Hashing & KDFs: MD5, SHA256, HMAC_SHA256, HKDF_SHA256, PBKDF2_HMAC_SHA256 - Protocols & Randomness: SPAKE2P_Matter, random

    Berry Console in the Web UI¶

    You can write and execute multi-line Berry scripts live in the browser using the Berry Console panel of the Web Interface. The Berry console executes code directly in the persistent device VM without recompiling firmware.

    Pure-Python Solidification (berry_port)¶

    During native builds (tools/newmota/berry.py), Newmota uses berry_port, a pure-Python line-by-line port of the ANSI C99 Berry interpreter. It solidifies Berry scripts into immutable C bytecode structures placing constant tables in flash memory, eliminating the need for a host C compiler during firmware builds.

    Loading files¶

    load("driver.be") (also newmota.load) compiles and runs a Berry source file from the filesystem. A missing leading / and .be extension are added. It returns true on success and false on failure, which is logged. Files are compiled as a whole, so load driver classes before loading a separate script that uses them. .bec and .tapp files are not supported. A runtime-loaded class can replace a built-in class of the same name.

    Startup Script (/autoexec.be)¶

    Normal application images attempt /autoexec.be once on their first cooperative loop, after filesystem, settings, hardware, network, and the persistent Berry VM are initialized. Safeboot contains no Berry or startup-script code.

    • Missing file is silent. Compile, runtime, allocation, or deadline errors are logged and leave the VM usable for subsequent Br commands.
    • One persistent VM: created after filesystem and settings initialization, retains globals across Br commands and the startup script, destroyed only for an explicit Berry restart or application shutdown.
    • Bounded loader: loading reuses Berry's existing streaming source parser and its transient 256-byte input buffer. The Newmota port adds only a read-only LittleFS handle with a transient 512-byte LittleFS cache — it never allocates a buffer proportional to script size and contains no second parser.
    • Disable control: SetOption153 1 disables startup execution with Tasmota-compatible meaning; changing that option schedules the restart needed for the new policy to take effect.
    • Boot-loop protection: on ESP chips with RTC memory and Pico, quick restarts are counted without a flash write. From the fourth, autoexec.be and several automatic services are skipped; further fallback steps are described in Console & Commands. ESP32-C2, Beken, Bouffalo and AmebaD do not retain a count and always skip autoexec.be.

    ULP coprocessor¶

    Optional USE_BERRY_ULP exposes import ULP on ESP32, S2, S3, C5, C6, P4 and S31. It provides run([entry]), load(bytes), set_mem(pos, value), get_mem(pos), gpio_init(pin, mode), wake_period(index, us), adc_config(channel, attenuation, width) and sleep([seconds]). ULP.sleep closes MQTT and immediately sleeps until the ULP or the optional timer wakes the chip.

    ESP32 uses the ULP-FSM, S2/S3 use ULP-RISC-V, and C5/C6/P4/S31 use the LP core. The P4 supports LP ADC; ADC configuration raises an error on C5, C6 and S31. ULP ADC and Newmota's ADC driver cannot share ADC1. Hardware testing remains open.
