    Sensors & Environmental Readings¶

    Newmota includes a unified sensor architecture for environmental, temperature, humidity, pressure, and ambient light monitoring. Like all Newmota services, sensor drivers compile against native platform I2C and GPIO interfaces without Arduino layers, producing structured readings for the Web UI, status commands, and MQTT telemetry.

    Supported Sensors¶

    Sensor Type Measurements Bus / Interface Driver Feature
    BME280 Environmental Temperature, Relative Humidity, Barometric Pressure, Dew Point Shared I2C (0x76 or 0x77) USE_BME280
    BMP280 Barometric Temperature, Barometric Pressure Shared I2C (0x76 or 0x77) USE_BME280
    BH1750 Ambient Light Illuminance (Lux) Shared I2C (0x23 or 0x5C) USE_BH1750
    TC74 Temperature Temperature (°C / °F) Shared I2C (0x48–0x4F) USE_TC74
    DHT11 Temperature & Humidity Temperature, Relative Humidity Single Digital Pin (pulse timing) USE_DHT (GPIO_DHT11)
    DHT22 / AM2302 Temperature & Humidity High-precision Temperature, Relative Humidity Single Digital Pin (pulse timing) USE_DHT (GPIO_DHT22)
    SI7021 Temperature & Humidity Temperature, Relative Humidity Single Digital Pin (pulse timing) USE_DHT (GPIO_SI7021)
    BLE devices Radio sensors Temperature, humidity, pressure, illuminance, moisture, battery, weight, contact/motion/leak, events BLE advertisements USE_BLE_SENSORS (selects USE_BLE)

    BLE sensors are documented in Bluetooth & BLE Sensors. They are remote sensors: their temperatures never feed the global temperature.

    Enabling Sensors at Build Time

    Optional sensor drivers default to off to preserve flash budget on 2 MiB Compact profiles. Enable them in your user_config/<custom-id>.yaml configuration: 

    name: my-sensor-device
inherit: esp32c3-4m
features:
  USE_BME280: true
  USE_BH1750: true
    Selecting any I2C sensor automatically enables USE_I2C. make config offers the same choices in a menu.

    Hardware Configuration (GPIO)¶

    I2C Sensors (BME280, BMP280, BH1750, TC74)¶

    Assign hardware pins to I2C SCL and I2C SDA using the GPIO or Template commands: - Bus 1: I2C SCL (6) and I2C SDA (5) - Bus 2: I2C2 SCL and I2C2 SDA (where available)

    Ensure external pull-up resistors (typically 4.7 kΩ) are connected to both SCL and SDA lines. After assigning pins, restart the device (Restart 1).

    DHT / Single-Wire Sensors¶

    Assign the corresponding GPIO function to an available digital bidirectional pin: - GPIO_DHT11 for DHT11 - GPIO_DHT22 for DHT22 / AM2302 - GPIO_SI7021 for SI7021

    Sensor Driver Management (SensorDriver)¶

    Newmota allows inspecting, disabling, and enabling compiled sensor drivers at runtime:

    Command Syntax Description
    SensorDriver SensorDriver Lists all compiled sensor drivers and their IDs.
    SensorDriver <name> SensorDriver <name> Queries driver status, measurement fields, output routes, and enabled state.
    SensorDriver <name> 0 SensorDriver <name> 0 Disables driver probing and polling. Persisted across reboot.
    SensorDriver <name> 1 SensorDriver <name> 1 Enables driver and immediately triggers an initial probe. 
    > SensorDriver
{"SensorDriver":{"1":"BH1750","2":"TC74","3":"BME280","4":"DHT"}}

> SensorDriver BME280
{"SensorDriver":{"ID":3,"Name":"BME280","Field":"BME280","Routes":"StatusSNS,MQTT,Web","Enabled":1}}

> SensorDriver BME280 0
{"SensorDriver":{"ID":3,"Name":"BME280","Field":"BME280","Routes":"StatusSNS,MQTT,Web","Enabled":0}}

    Disabled drivers clear their retained samples and perform no I2C or GPIO polling, freeing shared buses for other tasks.

    Unit & Precision Settings¶

    Newmota stores canonical sensor samples in SI units (Celsius, %RH, hPa, Lux) and applies formatting and calibration consistently across all output surfaces (Web UI, JSON commands, and MQTT):

    Setting Command Range / Options Description
    Temperature Unit SetOption8 0 (Celsius), 1 (Fahrenheit) Selects output temperature unit. Default is Celsius (0).
    Pressure Unit SetOption24 0 (hPa), 1 (mmHg / inHg) Toggles pressure conversion. Default is hPa (0).
    Barometric InHg SetOption139 0 (mmHg), 1 (inHg) When SetOption24 1 is active, selects inches of mercury instead of mmHg.
    Temperature Resolution TempRes 0..3 Number of decimal places for temperature. Default is 1.
    Humidity Resolution HumRes 0..3 Number of decimal places for humidity. Default is 1.
    Pressure Resolution PressRes 0..3 Number of decimal places for pressure. Default is 1.
    Temperature Calibration TempOffset -12.6..12.6 Signed offset in tenths of a degree (applied in the selected temperature unit).
    Humidity Calibration HumOffset -10.0..10.0 Signed offset in tenths of a percent relative humidity. 
    > SetOption8 0
{"SetOption8":"OFF"}

> TempRes 2
{"TempRes":2}

> TempOffset -0.5
{"TempOffset":-0.5}

    Telemetry & Output Surfaces¶

    Status Command (Status 10 / StatusSNS)¶

    Query the latest sensor readings from the console or scripts:

    > Status 10
{"StatusSNS":{"Time":"2026-10-19T14:30:00","BME280":{"Temperature":21.4,"Humidity":52.3,"DewPoint":11.2,"Pressure":1013.2},"BH1750":{"Illuminance":320},"TempUnit":"C"}}

    If a sensor reading fails, the missing field is omitted until the next successful measurement rather than reporting corrupted or stale data. The canonical sensor snapshot is limited to 1024 payload bytes; if serialization would exceed that, publication is skipped with a log warning and the previous snapshot remains visible.

    MQTT Telemetry¶

    When MQTT is enabled, sensor readings are published periodically on the tele/<topic>/SENSOR topic at the cadence set by TelePeriod:

    tele/newmota_A1B2C3/SENSOR = {
  "Time": "2026-10-19T14:30:00",
  "BME280": {
    "Temperature": 21.45,
    "Humidity": 52.3,
    "DewPoint": 11.2,
    "Pressure": 1013.25
  },
  "TempUnit": "C"
}

    A driver with events (a BLE button, motion edge, door change, scale weight and so on) also publishes unsolicited tele/<topic>/SENSOR messages as {"<device>":{...}}, immediately when the event arrives. BLE event messages carry RSSI and MAC without Time, matching the periodic message. A message the MQTT queue cannot take is retried and dropped after a bounded delay. See Bluetooth & BLE Sensors.

    Web Interface & REST API¶

    • Web UI Sensor Panel: Connected sensors automatically appear on the main device web dashboard with their respective units, icons, and real-time values. Every known BLE device gets a card, with RSSI, Battery, LastSeen and NMT in a small footer; ages count up in the page.
    • GET /api/sensors: Returns raw canonical measurement documents.
    • GET /api/sensors/readings: Returns formatted readings with projected display labels and units for browser clients. Every reading except derived dew point also carries a series id.
    • GET /api/sensors/updates: Returns only sensors with new data since the last poll, as StatusSNS members plus dashboard-only fields. Every received BLE packet, or a changed local value, marks that sensor in the session's mask.
    • GET /api/sensors/updates/all: Marks every sensor first, for a page that draws all sensors.
    • GET /api/sensors/history/<series>: Returns one reading's last 24 hours as {"step":<seconds>,"values":[...]}, oldest first with null for gaps.

    The updates response holds as many sensors as fit; "more":true says others are waiting and "reset":true asks the page to fetch everything again. "heap" is included about every 10 seconds. While Home or Info is open the page asks about four times a second, waiting for each answer before the next, and redraws only the sensors in that answer. History is fetched one series at a time, each at most once a minute, and footer fields fetch no history.

    Sensor History¶

    Every reading keeps a 24-hour history for its dashboard card, in the card's units and with its offsets, including samples taken before a setting changed. The page draws it under the measurement's row.

    • Samples are taken every 10 seconds.
    • By default each series holds 24 hourly averages (about 48 bytes per series).
    • SetOption177 1 keeps 5-minute averages instead (288 slots, about 576 bytes per series). It takes effect after a restart; if the memory is not available at boot, history falls back to hourly with a log line.
    • Up to 32 series are kept. A series without samples for a day makes room for a new one.
    • History lives in RAM and starts empty after a restart.
    • Dew point is not recorded, because it is derived from temperature and humidity.
    • Ages (LastSeen, NMT) are stored as presence: 1 for a period in which the age was below one minute, so a BLE device's visibility over the day shows at a glance.

    I2C Bus Diagnostic Scan (I2CScan)¶

    When USE_I2C is enabled, the I2CScan command tests both logical I2C buses for connected devices:

    > I2CScan
{"I2CScan":"Device(s) found on bus1 at 0x23 0x76"}
    • Address Range: Probes valid non-reserved 7-bit addresses 0x08 through 0x77.
    • Dual Bus Support: If two logical buses are active, results are returned in bus order: 
      {"Results":[{"I2CScan":"Device(s) found on bus1 at 0x76"},{"I2CScan":"No devices found on bus2"}]}
    • Error Reporting: If an I2C bus error occurs (e.g. missing pull-up resistors or bus stall), an error code and failing address are reported (e.g. {"I2CScan":"Error 5 at 0x08 on bus1"}).

    TuyaMCU sensors¶

    With USE_TUYA_MCU_SENSORS, mapped MCU data points appear as TuyaSNS in sensor telemetry and on the dashboard. See TuyaMCU sensors for mappings, precision and reporting behavior.
