    Console & Commands¶

    This is the command reference for everyday life with your device — over the serial cable or in the web console. Commands are case-insensitive, every answer is JSON, ? asks instead of changing, and prefixing _ runs a command quietly (handy in scripts). If you're new, start with First Steps; if you arrive from Tasmota, read Coming from Tasmota first.

    The ten commands you'll use most: Status, Power, Dimmer, SetOption, SSId/Password, Module/Template/GPIO, Restart, Reset, Time, Br.

    Files and stored settings have their own guide: Files & Settings.

    Console & Command Engine¶

    The runtime console accepts case-insensitive text commands over serial/USB, the browser console, MQTT, and Berry, producing structured JSON responses.

    Platform consoles: ESP-IDF uses one application console with dynamic USB/UART0 selection; Beken uses the SDK's selected log UART (UART1 on current BK7231N/BK7238 BDK profiles, polling the SDK's interrupt-fed software FIFO, no character echo); Pico uses native USB CDC. See the device pages for platform details.

    Application images timestamp each result line on the serial console and in the Web Console with HH:MM:SS.mmm, matching the log timestamp and Tasmota's RSL:-style framing, but without an RSL: label — the JSON follows directly. MQTT and POST /api/command stay plain JSON. Every line of a multi-line result is stamped.

    Command execution flows through a centralized processor shared across all target platforms:

    • Case-Insensitive Matching: Commands like STATUS, status, Status, SetOption0, and setoption0 are treated identically.
    • Structured JSON Output: All command feedback is formatted as valid JSON.
    • Quiet Mode Execution: Prefixing any command with an underscore (_) executes the command normally while suppressing external output (useful in automated batch scripts or Berry scripts).
    • Querying Values: Passing ? or invoking a command without arguments queries its current state.
    > Status 2
{"StatusFWR":{"Version":"<version>","BuildDateTime":"2026.10.02 11:27:07","Platform":"ESP-IDF","SDK":"v5.5","Hardware":"esp32c2"}}

> _SetOption0 1
(executed silently without external JSON output)

    Synchronous Command Chains¶

    In place of Tasmota's deferred Backlog queue, Newmota accepts bounded synchronous command chains delimited by semicolons. To run part of a line later, use Defer:

    Module 0; GPIO1 224; Restart 1
    • Semicolon Delimiter: Chains up to 16 commands in a single line. Semicolons inside JSON strings or balanced curly braces ({}) are preserved.
    • Pre-Validation: The complete chain is structurally validated before any handler runs. An invalid command or syntax error rejects the entire chain.
    • Reboot Guard: Any command that triggers a restart (such as Restart 1 or Reset) must be the final command in the chain.
    • Single Framed Result: Newmota returns one JSON object per command request, with ordered component results placed in a Results array.
    • Berry Execution: In Berry scripts, newmota.cmd("cmd1; cmd2") executes the chain and returns results as an iterable map.

    Deferred Commands (Defer)¶

    Defer <ms> <command> runs a command line later, once <ms> milliseconds (0 to 3 600 000, one hour) have passed since the Defer command ran. Newmota has no Backlog, Delay or NoDelay; Defer replaces them:

    > Power1 ON; Defer 2000 Power1 OFF; Defer 4000 Power1 ON
{"POWER1":"ON"}
{"Defer":{"Ms":2000,"Pending":1}}
{"Defer":{"Ms":4000,"Pending":2}}
    Command Action
    Defer <ms> <command> Schedules the command line; answers {"Defer":{"Ms":<ms>,"Pending":<n>}}.
    Defer / Defer ? Shows how many lines are waiting: {"Defer":{"Pending":<n>}}.
    Defer Cancel Cancels every waiting line: {"Defer":{"Cancelled":<n>}}.
    • Checked in advance: the deferred line is checked with the chain rules when it is scheduled and may be at most 128 bytes. A chain inside it needs escaped semicolons: Defer 5000 Power1 OFF\; Power2 OFF. A command can still refuse its value when it runs.
    • Same source: the line runs as if sent again from where the Defer came from (serial, web, MQTT, Berry). Its answer appears on the serial console, in the Web Console and on stat/<topic>/RESULT. A deferred Status 0 from MQTT answers section by section on MQTT, like a direct one. On an MQTT group topic, the deferred line must pass the same group-topic check as a direct command, and a Defer inside it is refused.
    • Limits: eight lines can wait at the same time; a ninth answers {"Defer":"Full"}. One line runs per main-loop pass, the earliest due first; lines due at the same time run in the order they were scheduled. Timing follows the main loop, so a line can run up to the Sleep period late.
    • Restart: waiting lines live in RAM only. A requested restart or deep sleep drops them, and while one is pending Defer answers {"Defer":"Restarting"}. For a relay that must switch off even across a restart or power loss, use PulseTime.

    System & Restart Commands¶

    System lifecycle operations: Restart 1 for a graceful reboot, Restart 3 to switch to the recovery image, Restart 99 for an immediate reboot.

    Command Action
    Restart / Restart ? Displays syntax helper ({"Restart":"1 to restart"}).
    Restart 1 Performs a normal graceful, delayed restart.
    Restart 3 Safeboot partition toggle (also behind "Upload firmware file" on the web Firmware Update page): implemented for ESP-IDF and the AmebaD, Bouffalo, and Picos; Beken returns an explicit unsupported result. The cross-platform feature is not marked complete.
    Restart 99 Triggers an immediate hardware reboot.

    Boot-loop fallback¶

    On ESP chips with RTC memory and Pico, consecutive restarts, watchdog resets or panics within ten seconds of starting the application trigger a temporary fallback. Power-on, brownout and deep-sleep wakes reset the count.

    • From the fourth quick restart, BLE, Matter and LVGL autostart and autoexec.be are skipped.
    • From the fifth, saved GPIO overrides are ignored for that boot; module and template assignments still apply. The GPIO command continues to show the saved overrides.
    • From the tenth, the application clears the count and restarts into its paired Newmota Safeboot before mounting the filesystem. If Safeboot is unavailable, it continues the reduced boot. Restart 3 in Safeboot returns to the application.

    The fallback does not change settings. A reduced boot logs the count, includes BootLoop in Status 1, and shows it on the web Information page. SetOption115 1 and lv.start() can still start BLE and LVGL manually. ESP32-C2, Beken, Bouffalo and AmebaD do not retain the count, so they do not use this fallback and always skip autoexec.be. Hardware testing remains open.

    Safeboot Partition Switching (Restart 3)¶

    Restart 3 never guesses a boot target. ESP-IDF accepts it only when the running partition table contains the expected single-OTA Tasmota layout — it then modifies the otadata partition sector to point to the alternate partition (app0 ↔ safeboot) and reboots. If the alternate partition is absent or invalid, it returns {"Restart":"Safeboot unavailable"} without altering boot state.

    The AmebaD uses only its checked-in OTA1/OTA2 layout and restores the destination signature before invalidating the current image; repeated Restart 3 switching has been exercised on BW16 hardware. The Bouffalo flips the FW active index through the CRC-protected inactive table copy and re-reads the tables to verify the switch. The Pico arms a power-cycle-persistent request in its marker sector and chains into Safeboot from the entry point; a failed chain clears the request so a corrupt Safeboot image cannot reboot-loop. Beken deliberately returns an explicit unsupported result because its active stock single-application layout has no alternate image. On a device migrated from Tasmota, ESP-IDF can also enter Tasmota's own verified Safeboot image (see Switching From Tasmota). Tasmota's halt and deliberate crash/watchdog restart modes are not implemented. Timed deep sleep is a separate optional feature; see Wi-Fi, Time & Status.

    Factory & settings reset (Reset)¶

    Command Action Description
    Reset / Reset ? Syntax helper Returns {"Reset":"1 to reset"}.
    Reset 1 Default reset Restores default parameters, rewrites LittleFS settings, and restarts.
    Reset 2 Clean erase reset Erases settings and rewrites fresh minimal defaults.
    Reset 3 Radio PHY erase Erases native radio PHY calibration (ESP-IDF) and restarts to re-calibrate.
    Reset 4 Keep Wi-Fi reset Restores default parameters while preserving Wi-Fi credentials.
    Reset 5 / Reset 6 Clean reset (keep Wi-Fi) Erases settings to defaults while preserving Wi-Fi credentials.

    Persistent settings¶

    Newmota stores your configuration in a checksummed file with a previous-generation fallback, so an interrupted save never corrupts your setup. A success reply means the change is safely on flash.

    Storage layout, what survives updates, backups: Files & Settings.

    Configuration & Option Commands¶

    SetOption / SO — Option Configuration¶

    Newmota accepts Tasmota-compatible SetOption numbers (slots 0 through 177):

    • Boolean Options (0–31, 50–177): Controlled using 0/OFF/false or 1/ON/true. Returns {"SetOption<n>":"OFF"} or {"SetOption<n>":"ON"}.
    • Parameter Options (32–49): Stores 8-bit unsigned values (0 to 255). Returns {"SetOption<n>":<value>}.

    Accepting or reporting a slot does not mean its Tasmota behavior is implemented; unlisted slots are stored for compatibility and have no effect. Slot 34 can be queried but cannot be changed through this command. The general boolean list reports through slot 165; query slot 177 directly. Implemented slots include SetOption60 (normal sleep), SetOption115 (BLE), SetOption127 (disable Wi-Fi power saving), SetOption151 (Matter) and SetOption177 (5-minute sensor history); the firmware repository's SETOPTION.md is the complete list with defaults.

    > SetOption0 1
{"SetOption0":"ON"}

> SetOption32 200
{"SetOption32":200}

    Option Reporting¶

    Invoking SetOption without an index generates packed status reports:

    • SetOption: Returns an inverted list of all boolean options ({"SetOption":"!0,1,!2..."}).
    • SetOption 0: Returns the enabled booleans plus the SetOption32_49 parameter byte array.
    • SetOption 1: Returns only the enabled booleans in array format ({"SetOptionSet":[1,3,10]}).
    • SetOption 2: Returns only the SetOption32_49 parameter byte array.

    Wi-Fi Credential Management¶

    • SSId / SSId1 / SSId2: Query or update Wi-Fi SSID for slot 1 or 2. E.g. SSId1 MyNetwork. Returns {"SSId1":"MyNetwork"}.
    • Password / Password1 / Password2: Sets Wi-Fi passphrase. Password queries always return masked strings ({"Password1":"****"}).

    WebPassword — Web Access Credential¶

    Provisions the device-hosted web UI password. Initial provisioning and password changes require the physical serial console; the reply is always masked.

    > WebPassword your-device-password
{"WebPassword":"****"}

> WebPassword 0
{"WebPassword":"****"}

    Use 8..64 bytes; WebPassword 0 clears the credential and leaves web access open without authentication, matching standard Tasmota behavior. Password changes and settings resets invalidate all active sessions. See Web Interface.

    DeviceName — Device Identity¶

    Sets or queries the persisted, human-readable device name (bounded to 31 bytes):

    > DeviceName KitchenPlug
{"DeviceName":"KitchenPlug"}

    SerialLog / WebLog — Log Level Control¶

    Persistent Tasmota-compatible log thresholds, stored in settings (defaults: serial 2, web 2; maximum 4):

    > SerialLog 3
{"SerialLog":3}

> WebLog
{"WebLog":2}

    SerialLog applies to the runtime serial threshold immediately. WebLog threshold is stored and kept in sync.

    Sleep, Wi-Fi power & buttons¶

    Command Syntax Description
    Sleep Sleep [0..250] Sets the dynamic loop sleep in milliseconds (default 50). Values above 50 are stored but act as 50. 0 disables Wi-Fi power saving.
    WifiPower WifiPower [0 \| 1 \| <dBm>] ESP-IDF only. Sets fixed transmit power, the chip default (1), or RSSI-based power (0).
    ButtonDebounce ButtonDebounce [40..1000] Sets the button filter/handler time in milliseconds (default 50). Values ending in 9 select an unimplemented native AC mode and are rejected.

    Bluetooth¶

    BLE scan controls are covered in Bluetooth & BLE Sensors:

    Command Syntax Description
    BLEActive BLEActive [0\|1] Passive (default) or active scanning.
    BLEScan BLEScan <interval>,<window> Scan timing in milliseconds, 3–640, window ≤ interval.
    BLEWatch BLEWatch [<MAC>[,<type>] \| 0] Manages the watched-address list.

    With USE_BLE_SENSORS, MI32Key, MI32Name, MI32Cfg and MI32Option0–MI32Option3 / MI32Option5 configure device keys, names and event behavior. MI32Cfg writes devices, keys and names to /mi32cfg; the options last until reboot. See Bluetooth & BLE Sensors.

    Matter¶

    With USE_MATTER, the stack answers three commands while it runs (otherwise each returns {"<command>":"Off"}):

    Command Syntax Description
    MtrInfo MtrInfo Fabrics, endpoints, enforcement state, window, and pairing/QR data while open.
    MtrJoin MtrJoin [0\|1] Opens (1) or closes (0) a commissioning window; no argument queries.
    MtrReset MtrReset 1 Removes every fabric and opens a commissioning window.

    See Matter for commissioning, the bridge, access control and storage.

    Telemetry & Status Commands¶

    The Status command family reports diagnostic metrics. On the console, in Berry and over HTTP, Status and Status 0 return one combined object. Over MQTT, both publish the sections separately on STATUS, STATUS1, STATUS2 and so on, because the combined object would exceed the 1024-byte MQTT response limit; a request from elsewhere also publishes the sections while MQTT is enabled. Safeboot, whose object fits, stays combined on STATUS0. (Status 5 network and Status 7 time details live on their own page: Wi-Fi, Time & Status.)

    Section Command Output Object Description
    0 Status / Status 0 Status General summary: module, DeviceName, power mask, PowerOnState, LED, save and retain settings, plus all available sections
    1 Status 1 StatusPRM Baudrate, GroupTopic, OtaUrl, RestartReason, Uptime/StartupUTC, stored Sleep, BootCount, SaveCount, RestartRequired
    2 Status 2 StatusFWR Firmware version, build timestamp, platform, SDK version, and target chip
    3 Status 3 StatusLOG Serial/Web log levels, configured SSIDs, TelePeriod, then five compact SetOption bitfield words plus the SetOption32_49 hex string
    4 Status 4 StatusMEM Memory statistics & heap telemetry
    5 Status 5 StatusNET Network details, plus WifiPower on ESP-IDF (see Wi-Fi, Time & Status)
    6 Status 6 StatusMQT MQTT connection details; requires an MQTT-enabled build
    7 Status 7 StatusTIM Time, source validity, RTC, GPS, and NTP-server diagnostics
    8, 10 Status 8 / Status 10 StatusSNS Sensor and energy readings
    9 Status 9 StatusPTH Energy power-delta and P/V/I thresholds (needs USE_ENERGY_STATUS9)
    11 Status 11 StatusSTS Live state (relays, lights, Wi-Fi, memory, diagnostics)
    12 Status 12 — Always unavailable (no crash capture)
    13 Status 13 — Always unavailable (no shutters)

    Sections without a backing feature are errors when requested individually and are left out of Status 0, matching Tasmota: Status 6 without MQTT, Status 9 without energy, and Status 12/Status 13 everywhere. StatusPRM.RestartReason reports one of Power On, Software, Watchdog, Panic, Brownout, Deep Sleep or External; where the platform cannot determine it the field is omitted. Bouffalo always counts as unknown. A blocked loop is not detected. MQTT Info3 uses Power On or Restart when the reason is unknown.

    BuildDateTime (form YYYY.MM.DD HH:MM:SS) tells you exactly when your firmware was built — one timestamp per build, shared by the application and its Safeboot companion, and recorded in the package manifest too. Note that Platform replaces the Arduino-specific Core.

    StatusMEM Telemetry Details¶

    Status 4 reports available platform memory metrics without dynamic memory allocation. In Newmota, dynamic metrics (Free, Heap, StackLowMark, PsrFree) are reported in bytes, while fixed capacity metrics (ProgramSize, ProgramFlashSize, FlashSize, PsrMax) are reported in KiB:

    > Status 4
{"StatusMEM":{"ProgramSize":896,"Free":1179648,"Heap":188416,"StackLowMark":6144,"ProgramFlashSize":2048,"FlashSize":2048}}
    • ProgramSize: Firmware binary size in KiB.
    • Free: Remaining partition capacity in bytes.
    • Heap: Real-time free system heap memory in bytes.
    • StackLowMark: Lowest remaining FreeRTOS/runtime task stack watermark in bytes.
    • PsrMax / PsrFree: Total external PSRAM (KiB) and free PSRAM (bytes), present only when PSRAM is supported and initialized.
    • ProgramFlashSize / FlashSize: Configured and total physical flash capacity in KiB.

    Network & Diagnostic Commands¶

    Command Syntax Description
    Hostname Hostname Queries the current runtime network hostname.
    IPAddress IPAddress or IPAddress<1..5> Queries all configured addresses (1: IP, 2: Gateway, 3: Subnet, 4: DNS1, 5: DNS2) or one indexed address.
    WifiScan WifiScan [1] Triggers an asynchronous Wi-Fi scan and returns detected networks (SSID, RSSI, channel, BSSID, encryption).
    WifiTest WifiTest <ssid>,<password> Tests candidate station credentials without saving them or disconnecting active interfaces. Joins the first access point with that SSID it finds; 9 s limit (12 s on BL602).
    Ping Ping <host> or Ping<0..8> <host> Runs an asynchronous IPv4 ICMP ping campaign. Ping sends 1 probe; Ping1–Ping8 send N probes; Ping0 makes up to four attempts and stops at the first reply. Querying reports campaign statistics.
    wget wget <URL> Asynchronously downloads direct HTTP 200 file from URL to LittleFS (saving to URL basename or /index.html), atomically replacing on success.
    I2CScan I2CScan Probes active logical I2C buses across the non-reserved address range 0x08 through 0x77.

    See Wi-Fi, Time & Status for full station and SoftAP onboarding details.

    Optional Text & Temperature Commands¶

    • StateText1–StateText4 (USE_STATE_TEXT): durable aliases for the state words OFF, ON, TOGGLE, and HOLD in Power responses, STATE, MQTT Power publications, and energy margins. StateText queries all four; aliases are 1..31 bytes, spaces become underscores, and numeric/standard ON/OFF/TOGGLE input parsing is unchanged.
    • GlobalTemp / GlobalTemp2 (USE_GLOBAL_TEMPERATURE_COMMANDS): GlobalTemp queries or manually sets the shared temperature used by energy over-temperature protection (input follows SetOption8, answers are always Celsius at one decimal, null when unavailable); GlobalTemp2 0..250 selects which reported temperature field feeds it automatically (0 = raw automatic observation).

    Optional Display & Audio Commands¶

    Display Commands (USE_DISPLAY)¶

    When compiled with USE_DISPLAY: true and /display.ini panel descriptor: - Display / Display ?: Reports panel availability, descriptor name, resolution, dimmer, rotation, inversion, power. - DisplayDimmer 0..100: Adjusts panel brightness percentage (0 powers off; nonzero powers on). - DisplayRotate 0..3: Changes panel rotation and updates logical dimensions. - DisplayInvert 0\|1: Toggles panel color inversion. - DisplayPower OFF\|ON\|TOGGLE: Switches panel power on or off. - DisplayRefreshNow [0\|1]: Triggers full (0) or partial (1) e-paper panel refresh.

    Transports, QSPI, and touch setup are covered in Displays & Touch.

    Audio Commands (USE_I2S)¶

    See Audio for setup, Berry sessions and external codec drivers. When compiled with USE_I2S: true (requires >= 4 MiB flash): - I2SPlayN /file: Streams encoded MP3 (1), AAC (0), or Opus (2) file to I2S output. - I2SLoopN /file: Loops encoded audio file repeatedly. - I2SRecN /file: Records microphone input to compressed MP3 or Opus file (I2SRec stops; I2SRec -? queries elapsed time). - I2SWrN URL: Plays HTTP/ICY audio stream over Wi-Fi. - I2SStream 0|1: Controls local port-81 microphone streaming listener. - I2SConfig: Saves separate RX and TX profiles, including mode, rate, framing and gain. For example, I2SConfig Rx.rate 16000 changes one field; JSON can change several atomically. I2SConfig reset restores defaults. Changes require the command operation to be stopped. I2SGain changes live gain; an I2SConfig save persists the live gains. Platform-specific options and framing support vary by chip; see the firmware repository’s src/app/drivers/audio/README.md.
