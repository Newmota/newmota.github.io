    Audio¶

    Newmota can play and record audio through I2S, control sessions from Berry, and configure supported external codecs and amplifiers. Audio is optional, excluded from standard builds, and still awaiting hardware qualification. It needs at least 4 MiB of flash. Beken support is deferred; BL602 has no I2S peripheral, and BL616/BL618DG do not yet have a Newmota I2S adapter. Available pins and modes depend on the chip.

    Enable audio¶

    Choose features in make config or in a personal build by hand, selecting only the codecs you need:

    name: audio-s3
inherit: esp32s3-qio-qspi
features:
  USE_I2S: true
  USE_AUDIO_MP3: true
  USE_AUDIO_AAC: true
  USE_AUDIO_OPUS: true
  USE_WEB_AUDIO: true

    USE_I2S enables the transport and commands; USE_BERRY_AUDIO adds the Berry audio module. MP3 and Opus support playback and recording; AAC supports ADTS playback only. USE_AUDIO_SAM adds speech. The Berry module brings a microphone level meter, a spectrum analyzer and a tone generator (RTTTL on I2S). USE_WEB_AUDIO requires the web interface and adds a Home player when an I2S output is configured. Files stream through the filesystem rather than being loaded entirely into RAM; PCM and WAV files are not supported.

    Configure I2S¶

    Assign the I2S GPIO functions in the device template. Standard output uses BCLK, WS and DOUT; an input uses DIN as well as its clocks. Some external codecs also need MCLK. Input (Rx) and output (Tx) have separate profiles, initially in standard mode. Select PDM explicitly for a PDM microphone; supported modes and pin routes depend on the chip. Pico and AmebaD do not support PDM.

    Use I2SConfig to inspect or save profiles, with the command operation stopped:

    I2SConfig
I2SConfig Rx.rate 16000
I2SConfig {"Rx":{"mode":"pdm","rate":16000,"slot_mask":1}}
I2SConfig reset

    Profiles include rate, bits, slot width, framing and gain. Settings are checked against the device before saving, and are retained across restarts. I2SGain adjusts live playback volume; saving I2SConfig also stores the live gains. Reset restores template-derived defaults. Pins come from the template, not the saved profile. See the firmware repository's src/app/drivers/audio/README.md for platform-specific options and supported formats.

    Play and record¶

    Commands share a session across the console, web, MQTT and Berry command interface. They cannot take over an active Berry audio session. For example, I2SPlay1 /chime.mp3 plays an MP3, I2SLoop1 /chime.mp3 repeats it, and I2SRec1 /recording.mp3 records MP3. Stop recording with I2SRec so it can finalize; I2SStop stops the command session. I2SPause pauses file playback, and a bare I2SPlay or I2SLoop resumes it.

    Playback selectors are 0 for AAC, 1 for MP3 and 2 for Opus; an omitted selector is 0. Recording uses 1 for MP3 or 2 for Opus and defaults to 1. The selected codec must be compiled in. I2SWrN plays a plaintext HTTP/ICY stream; HTTPS and redirects are not supported. I2SStream 1 starts the microphone HTTP listener on port 81. See audio commands for the command list.

    Berry audio sessions¶

    Berry controls native sessions through audio.Session. Configure the board's output pins first, then for example:

    import audio
s = audio.Session({
  'source': 'file', 'sink': 'output', 'codec': 'mp3',
  'location': '/announcement.mp3', 'loop': false
})
s.start()
s.status()

    Input and output maps start with the saved Rx and Tx profiles and can override settings and pins for a session. Recording uses source: 'microphone', sink: 'file', an enabled encoder and a file location. Hardware and pin ownership are shared, so conflicting sessions report Busy.

    Call s.stop() and poll s.status() until state 2 (ended) before s.close(). Closing immediately can abort a recording before its final data is written. A completed session retains its hardware lease until closed; it can instead be reconfigured for another operation once ended. Status state 0 is closed, 1 running and 3 failed.

    With the respective features enabled, audio.level and audio.spectrum analyze microphone input using the Rx profile. They are singletons and compete for the input; stop one before starting the other. Level readings are dBFS unless calibrated with audio.level.offset(). Spectrum results are available through audio.spectrum.bands().

    Board audio codecs and amplifiers¶

    Berry drivers in berry/drivers/audio/ configure external audio chips over I2C. They require USE_I2C and USE_I2S; ES8311, PCM5122 and TAS58xx also require USE_BERRY_GPIO. The drivers can be uploaded and loaded at startup or included with a personal build's solidify list.

    Driver Hardware
    es8311.be Mono DAC and microphone ADC, with optional amplifier enable
    es7210.be Four-channel microphone ADC
    es8388.be Stereo DAC and ADC
    es8156.be Stereo DAC
    es7243e.be Stereo microphone ADC
    pcm5122.be Stereo DAC, with optional soft-mute pin
    tas58xx.be TAS5805M and TAS5825M Class-D amplifiers, with optional power-down pin

    For example, configure the board's I2C and I2S pins and enable USE_BERRY_DRIVERS, then load and register an ES8311 in /autoexec.be:

    load("es8311.be")  # omit when solidified
codec = ES8311(53)  # replace 53 with the board's amplifier-enable GPIO, or nil
newmota.add_driver(codec)

    Registration lets the ES8311 follow output power and stream rate. The ES7210 follows input rate; the PCM5122 and TAS58xx follow output power. The audio hook runs on the next Berry poll, so an amplifier may miss the first milliseconds of a stream. The ES8311, ES7210, ES8388 and ES7243E require I2S MCLK at 256 times the sample rate (384 times for 24-bit ES8311); PCM5122 derives its clock from BCLK. Check each driver's header and the firmware audio README for supported formats, pin wiring and controls. The TAS58xx keeps its output off after DC or over-current faults until activate() is called.
