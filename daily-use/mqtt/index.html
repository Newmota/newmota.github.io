    MQTT & Telemetry¶

    Newmota implements a first-class, bounded MQTT client and canonical telemetry service across all five Wi-Fi platform families (ESP32, Raspberry Pi Pico 2 W, Beken BK7231, Bouffalo, AmebaD BW16). MQTT is plain text today; secure MQTT over TLS remains future work.

    Architectural Principles¶

    1. Zero-Heap Framing: Packet serialization and deserialization use the pinned coreMQTT v2.3.1 serializer without dynamic heap allocation. Packets are bounded to a maximum of 1280 bytes.
    2. Canonical Message Model: MQTT, the device-hosted Web UI, and Berry share the same canonical state router. Relays, telemetry snapshots, and command results use identical JSON structures across all interfaces.
    3. Fail-Closed Plain IPv4 Transport: The current runtime path connects via nonblocking raw-TCP streams over lwIP. Encrypted TLS MQTT settings are stored but fail closed until a hardware-tested native TLS adapter is linked.
    4. Safeboot Parity: Network-capable Safeboot images compile the same bounded MQTT client and command path, using the paired application's persisted broker settings (disabled by default until configured).

    Configuration Commands¶

    MQTT broker settings are persisted atomically in LittleFS settings under /.newmota/.

    Command Syntax Description
    Mqtt Mqtt Queries the full MQTT configuration summary.
    MqttHost MqttHost [hostname \| IP \| 0] Sets broker hostname or IPv4 address. 0 clears the host.
    MqttPort MqttPort [1..65535] Sets broker port (default: 1883).
    MqttUser MqttUser [username \| 0] Sets broker authentication username. 0 clears.
    MqttPassword MqttPassword <secret \| 0> Sets broker password. Serial-console only; query replies are always masked (****).
    MqttClient MqttClient [client-id \| 0] Sets client identifier (defaults to newmota_<MAC>).
    MqttTopic MqttTopic [topic] Sets the base device topic (defaults to newmota_%06X). Must not contain MQTT wildcards (+, #).
    MqttKeepAlive MqttKeepAlive [1..65535] Sets MQTT ping keep-alive interval in seconds (default: 60).
    MqttEnable MqttEnable [0\|1\|off\|on] Enables or disables the MQTT client service.
    TelePeriod TelePeriod [0 \| 1 \| 10..3600] Sets periodic telemetry cadence in seconds. 0 disables periodic reports; 1 restores the 300 s default; querying TelePeriod triggers an immediate telemetry broadcast.

    Configuring in the browser¶

    The web UI's Configuration → MQTT page (and Beken's compact page) edits the same settings: broker, credentials, topics with live previews of the resolved topic paths, group topics, retain options, and keep-alive/retry/timeout/TelePeriod. Passwords are never read back (only whether one is set) and can be kept, replaced, or cleared explicitly. Saving a setting and the broker accepting a connection are reported separately, and Test runs a trial CONNECT through all subscription acknowledgements, pausing MQTT command delivery during the trial and restoring the normal client afterwards. The shared TCP stream cannot be borrowed while a firmware update or wget download is active.

    On an LED-equipped device, LedState bits 1 and 2 can flash the status LED for received and published MQTT messages, and the status LED blinks every two seconds while enabled MQTT is not connected (see Relays, Buttons & LEDs).

    Quick Setup Example¶

    From the serial console:

    > MqttHost 192.168.1.100
{"MqttHost":"192.168.1.100"}

> MqttUser homeassistant
{"MqttUser":"homeassistant"}

> MqttPassword secret-broker-password
{"MqttPassword":"****"}

> MqttTopic livingroom_plug
{"MqttTopic":"livingroom_plug"}

> MqttEnable 1
{"MqttEnable":"ON"}

    Once connected to your Wi-Fi network and broker, Newmota begins publishing telemetry and listening for commands.

    Topic Hierarchy¶

    Newmota adheres to standard Tasmota topic conventions:

    Direction Topic Pattern Payload / Purpose
    Inbound cmnd/<topic>/<command> Receives incoming commands (QoS 0).
    Outbound stat/<topic>/RESULT Immediate canonical command execution response.
    Outbound stat/<topic>/POWER<n> Dedicated power status on relay state changes.
    Outbound stat/<topic>/STATUS, STATUS1…STATUS11 Separate Status-section responses (STATUS0 carries a combined object on Safeboot).
    Outbound tele/<topic>/STATE Periodic telemetry heartbeat (uptime, Wi-Fi, memory, power states).
    Outbound tele/<topic>/SENSOR Periodic sensor snapshot and unsolicited sensor/BLE events.
    Outbound tele/<topic>/INFO3 Restart reason and firmware identity on boot.
    Outbound homeassistant/<platform>/<MAC>/<id>/config Retained Home Assistant discovery, one per entity (USE_HA_DISCOVERY).

    Status over MQTT¶

    Status 0 and Status0 do not return one combined object over MQTT. Both publish the available sections separately on stat/<topic>/STATUS, STATUS1, STATUS2 and so on, because the combined object does not fit the 1024-byte MQTT response limit. A request from elsewhere also publishes the sections while MQTT is enabled. On the console, in Berry and over HTTP, both return one combined object. Safeboot, whose object fits, stays combined on STATUS0.

    A publication larger than the packet limit is skipped with a log line instead of ending the session.

    Home Assistant discovery¶

    Images built with USE_HA_DISCOVERY publish Home Assistant's own MQTT discovery, so Home Assistant's MQTT integration (and openHAB or Domoticz, which read the same format) finds the device without further setup. This is Home Assistant discovery, not Tasmota's tasmota/discovery; the Tasmota integration in Home Assistant is not used.

    • One retained message per entity on homeassistant/<platform>/<MAC>/<id>/config, where <MAC> is the 12-digit station MAC. Entities: one switch per relay, one sensor per sensor reading (energy phases as array elements of ENERGY), the diagnostic sensors RSSI, Signal, Uptime and IP address, and a Restart button. Lights, switches and buttons follow later.
    • State comes from tele/<topic>/STATE and tele/<topic>/SENSOR; commands go to the normal cmnd/<topic>/... topics. Availability follows the LWT.
    • The device shows DeviceName (or the host name), the module or template name as model, Newmota as manufacturer, the firmware version, the MAC and a link to the web interface. A device with a single power output names its entity after the device; otherwise "Relay ". Rename entities in Home Assistant.
    • Messages go out 2–5 seconds after each MQTT connect, and again within about two seconds when something they depend on changes: DeviceName, the topics, SetOption19, the state texts, the relays or the set of sensor readings. They are paced through the MQTT queue.
    • An entity that disappears (a sensor removed, fewer relays) gets an empty retained message, which removes it from Home Assistant together with its user settings there. SetOption19 1 removes every entity this way; SetOption19 0, the default, publishes them again.
    • SetOption104 (no retain) also drops the retain flag of discovery messages, so Home Assistant then only learns about the device while it is running.

    USE_HA_DISCOVERY is off by default and selects USE_MQTT; it is currently enabled in the test environments while its size is measured. Switch it on in make config, or select it in a personal build by hand:

    features:
  USE_HA_DISCOVERY: true

    Matter bridge¶

    With USE_MATTER_BRIDGE, up to seven remote Tasmota devices appear as bridged Matter endpoints over MQTT. Discovery listens to tasmota/discovery/# (see Matter); bridged state is followed as each remote's state message arrives. Newmota publishes Home Assistant discovery, not Tasmota discovery, so Newmota remotes must be added explicitly.

    Inbound Commands via MQTT¶

    Newmota subscribes to cmnd/<topic>/#. The command suffix and message payload are fed directly into the shared application command processor:

    Single Commands¶

    • Publish to cmnd/livingroom_plug/Power1 with payload on $\rightarrow$ Relay 1 turns on, responds on stat/livingroom_plug/RESULT with {"POWER1":"ON"}.
    • Publish to cmnd/livingroom_plug/Dimmer with payload 75 $\rightarrow$ Adjusts dimmer, responds with {"Dimmer":75}.
    • Publish to cmnd/livingroom_plug/Status with payload 2 $\rightarrow$ Responds with StatusFWR firmware details.

    Semicolon Command Chains¶

    Incoming MQTT payloads support bounded synchronous command chains (up to 16 commands), validated atomically before execution:

    • Topic: cmnd/livingroom_plug/Power1
    • Payload: on; Dimmer 50; Color FF0000

    The result is published back to stat/<topic>/RESULT containing ordered results. To run part of it later, use Defer, for example on; Defer 2000 Power1 off; the deferred result is published on stat/<topic>/RESULT when it runs.

    Outbound Telemetry (tele/<topic>/STATE)¶

    On boot, after network association, and periodically on the cadence set by TelePeriod (default: every 300 seconds), Newmota publishes a complete system status report:

    {
  "Time": "2026-10-02T19:00:00",
  "Uptime": "0T01:23:45",
  "UptimeSec": 5025,
  "Heap": 184,
  "SleepMode": "Dynamic",
  "Sleep": 50,
  "LoadAvg": 19,
  "MqttCount": 1,
  "Berry": {"HeapUsed": 0, "Objects": 0},
  "POWER1": "ON",
  "POWER2": "OFF",
  "Dimmer": 80,
  "Fade": "OFF",
  "Speed": 1,
  "LedTable": "ON",
  "Wifi": {
    "AP": 1,
    "SSId": "MyHomeNetwork",
    "BSSId": "12:34:56:78:9A:BC",
    "Channel": 6,
    "Mode": "11n",
    "RSSI": 84,
    "Signal": -58,
    "LinkCount": 1,
    "Downtime": "0T00:00:00"
  },
  "Hostname": "newmota-A1B2",
  "IPAddress": "192.168.1.50"
}

    The fields follow Tasmota's order and formats, with Newmota's Band after Channel. RSSI is Tasmota's 0–100 quality value and Signal is dBm. Mode is reported only on ESP-IDF, the only backend that exposes the negotiated PHY mode; BSSId, Channel and Band appear after the first link refresh, about a second after connecting. Berry reports the last collection instead of collecting first, because the snapshot is rebuilt every 100 ms. Uptime comes from a 32-bit millisecond clock and wraps after 49.7 days. Safeboot keeps UptimeSec and the power fields.

    Querying TelePeriod on the console or over MQTT (cmnd/<topic>/TelePeriod ?) forces an immediate telemetry broadcast without resetting the timer cadence.
